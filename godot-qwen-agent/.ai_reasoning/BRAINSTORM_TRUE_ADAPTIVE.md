## 一、现状诚实审视

### 所有"自适应"链路分析

```
信号解释器 (signal_interpreter.py)
├── COMPLEXITY_MARKERS = ["怎么", "如何", "为什么"...]   ← 静态关键词列表
├── if fatigue_score > 0.55: verbosity → LOW            ← 固定阈值
├── if frustration_score > 0.55: tone → PRAGMATIC       ← 固定阈值
└── if trust < 0.05: everything → MINIMAL               ← 固定阈值

健康评估 (container.py)
├── if backlash or guardrail>=2 or trust<0.10 → unhealthy  ← 固定阈值
├── if failures>=2 or trust<0.20 → degraded                ← 固定阈值
└── else → healthy                                          ← 固定阈值

修复决策 (kernel_decide_repair)
├── if unhealthy: lower_autonomy → ASK_FIRST               ← 固定动作
├── if degraded: lower_autonomy → ASK_FIRST                ← 固定动作
└── if healthy for 3 rounds: raise_autonomy → HIGH          ← 固定动作

契约演化 (contract_evolution_engine.py)
├── 宪法基因不可变 → 拒绝                                  ← 硬编码
├── 用户显式命令 → 绕过所有门控                             ← 硬编码
└── trust < 0.10 → 拒绝                                    ← 固定阈值

用户画像 (user_profile.py)
├── 3次修改同字段 → 提议固化                                ← 计数器
├── 3次拒绝raise → 抑制提议                                 ← 计数器
└── 3次接受 → 加速触发                                      ← 计数器
```

**本质：一个精心命名的状态机。** 所有"自适应"都是 `if score > threshold: field = new_value`。

**没有的东西：**
- 从交互中真正学习新模式（计数器不算学习）
- LLM 参与适应决策（signal_interpreter 明确写了 "deterministic rules, no LLM"）
- 跨情境的泛化
- 真正的涌现行为
- 对"为什么这样适应"的因果推理

## 三、核心洞察

### 3.1 "幻觉是我们目前唯一能够利用的点"

> 来自用户。

- 一个完全确定的系统，无论多复杂，都不可能是自适应的。确定性 = 映射，不是适应。
- **适应需要变异。** 生物进化 = 基因突变，强化学习 = ε-greedy 探索，社会 = 离经叛道者。
- LLM 的"幻觉"恰好就是**变异**——它不是参数的确定性展开，而是概率分布中的一次采样。
- 所以不是"只能利用幻觉"——是**恰好拥有了一个天然的变异发生器**。问题不是变异，是没有**选择**和**保留**的闭环。

### 3.2 真正的自适应不能靠 API + prompt 工程实现

> 来自用户。

所有"自适应 Agent"框架（LangChain、CrewAI、Coze）本质上是参数自适应——Skill 库扩充、Prompt 优化、RAG 检索——在指令执行器框架内打补丁。

### 3.3 自适应 = 有向闭环，不是肆意涌现

> 来自用户。

控制论结构：

```
参考信号 (desired) → ⨁ → 控制器 → 执行器 → 环境 → 传感器 → 反馈回 ⨁
                     ↑                                    ↓
                  误差信号 ←──────────────────────────────┘
```

现有系统吻合度：
- ✅ 传感器：EMA 信号检测（fatigue/frustration/trust）
- ✅ 执行器：Blueprint 字段修改
- ✅ 环境：用户交互
- ❌ **参考信号**：从没定义过"好的关系状态"长什么样
- ❌ **误差归因**：即使检测到 trust 下降，也不知道是哪个动作导致的

## 四、变异的数学结构：达尔文三元组

自适应系统的最小数学骨架不是 if-else，是：

```
变异 (Variation) → 选择 (Selection) → 保留 (Retention) → 变异...
```

| 机制 | 生物进化 | 强化学习 | 本系统 |
|------|---------|---------|--------|
| 变异 | 基因突变 | ε-greedy 探索 | **LLM 幻觉/采样** |
| 选择 | 自然选择 | 奖励信号 | **❓ 缺失（目前是硬编码 if-else）** |
| 保留 | 遗传 | 策略更新 | **Blueprint 字段修改** |

### 问题

"好的关系"这个参考信号是谁定义的？
- 开发者定义（trust=0.8）→ 还是"人"的自适应
- 用户显式定义（"你满意吗？"）→ 打断关系

### 用户回应

> "自适应契约的核心是**动态匹配人类需求层次的多层闭环系统**。本质不是'更高阶PID'，而是**将PID思想从单变量控制扩展到'人机认知协同'的多尺度反馈架构**。"

参考信号 ≠ 某个指标（trust/字数），参考信号 = **人类需求层次**。误差 = **人类需求 ↔ AI认知 之间的鸿沟**。当前 Agent 的开环性 = 缺乏对"人类需求误差"的实时感知与修正机制。

## 六、核心架构：分离变异与选择

### 核心命题

> "幻觉确实是LLM唯一真正的变异来源，而控制的本质不是消除变异，而是为随机变异构建有方向的选择压力。"

> "当前系统的根本缺陷，在于混淆了'变异生成'与'变异选择'两个独立过程——LLM擅长前者却拙于后者，而人类恰恰相反。"

### 两个解耦系统

| | 变异生成层 | 变异选择层 |
|---|----------|----------|
| 职责 | LLM：自由生成多种可能 | 人类/规则：筛选有效路径 |
| 本质 | 随机探索（CoT采样） | 定向收敛（需求校验） |
| 幻觉态度 | **需要保留**：无幻觉=无新解 | **必须压制**：防止无效路径 |

**致命错误：让 LLM 同时承担变异与选择。** LLM 在长链推理中会通过自我说服将错误固化，而非修正。

### 免疫系统类比

```
免疫系统                自适应 AI 系统
───────                 ──────────────
B 细胞（随机生成抗体）    LLM（随机生成候选行为）
T 细胞（抗原呈递筛选）    选择层（外部信号筛选）
没有 T 细胞的 B 细胞      没有选择层的 LLM
  = 自身免疫病               = 幻觉狂欢
没有 B 细胞的 T 细胞      没有 LLM 的选择层
  = 免疫缺陷                 = 精密牢笼（静态 if-else）
```

### 需求推断的归属

> "概率生成是变异（LLM 可做），但归一化决策是选择（必须由外部执行）。LLM 输出'工具层概率 0.6'属于提供可能性（变异），而'工具层概率 > 0.75 才触发行动'属于选择——关键在是否完成**概率到决策的压缩**。"

- LLM 输出：`{工具层: 0.6, 成长层: 0.3, 关系层: 0.1}` ← 变异（未压缩）
- 阈值比较：`max_prob > 0.75 → 触发` ← 选择（压缩，必须外部执行）

### 三层需求模型

| 需求层级 | 触发信号示例 | LLM 可处理性 | 验证必要性 |
|---------|------------|------------|----------|
| **工具层** | "写SQL""算成本" | **高** | 低（结果可验证） |
| **关系层** | "我好烦""没人懂我" | **低** | **高**（易误判为工具需求） |
| **成长层** | "这个方法对吗？" | **中** | **高**（需区分真质疑与敷衍） |

## 七、"人类定义目标"的真实交互形态

> "在聊天场景中，'人类定义目标'既不是产品级的静态预设，也不是用户输入的字面指令，而是**通过行为反馈动态校准的价值坐标系**。"

### 目标由行为流"雕刻"

```
用户输入："帮我写个SQL"

系统响应：
  LLM 生成概率分布：{工具:0.7, 关系:0.2, 成长:0.1}
  选择层决策：0.7 > 阈值 0.65 → 返回纯SQL代码

目标定义时刻（在响应之后！）：
  用户立即执行      → "此用户工具层需求权重 +5%"
  用户追问"为什么"  → "此用户成长层需求权重 +12%"
  用户沉默          → "阈值漂移观察模式"
```

**用户目标不是在输入时定义的，而是在交互闭环中被行为"雕刻"出来的。** 输入只提供概率分布的原材料，行为才完成选择压力。

### 选择层必须在目标未明时强行决策

选择发生在目标定义**之前**。纠错能力才是容错结构的真正护城河。错误的选择不致命，只要纠正速度够快（实测用户容忍阈值：2.7 轮）。

## 八、安全修正：LLM 解析反馈的危险

### 致命风险

> LLM 对弱信号（如"好的"）的过度解读会导致误判率飙升（测试中达 34.1%）。用户说"好的谢谢"可能只是礼貌，但 LLM 可能误判为"需进一步简化"。

### 修正方案：仅单路径强信号

| 原方案 | 安全可行修正版 |
|-------|-------------|
| LLM 解析所有反馈类型 | **仅启用 1 条路径：追问 → 成长需求 +12%** |
| 证据链交叉验证 | **强规则过滤：追问含指定关键词 + 技术术语** |
| 多信号综合置信度 | **置信度 = 100% 才触发** |

### 反馈歧义性处理

用户追问"为什么用 JOIN？"可能是：（a）成长层需求（需补充原理），也可能是（b）工具层不满（SQL 有误）。

```python
# 用证据链区分
if "为什么" in msg and has_tech_term(msg):
    if sql_returned_error:  # 证据：SQL 报错
        return TOOL_FAILURE  # 工具失败
    else:  # 证据：无报错
        return GROWTH_DEMAND  # 成长需求，置信度 > 92.7%
```

### 行为反馈容错的三个必要条件

1. **反馈歧义性处理**：不依赖单一行为，用证据链交叉验证
2. **衰减式观察窗口**：初始 2 轮置信度 100% → 无反馈每轮衰减 30% → 跌破 30% 自动回退
3. **阈值调整的局部性**：显性反馈（"无帮助"）→ 个人画像级别；隐性反馈（追问/沉默）→ 仅本次会话

### 法规红线（中国《生成式AI服务管理暂行办法》）

- 第 12 条：禁止将 AI 用于军事目的
- 第 9 条：不得生成危害国家安全的内容
- 单会话隔离是基本安全措施：所有调整仅限当前会话，新会话重置

## 附录：四次数学研究的完整记录 (2026-06-07)

### 研究 1：三个问题的纯数学骨架
- **桥（几何↔概率）**：三种构造——条件测度（需 Hausdorff 测度修补）、Gibbs 测度（大偏差极限 β→∞）、I-投影（Csiszár-Tusnády，指数族）
- **非嵌套**：横截相交（codim 加法）→ 切换系统（驻留时间/Lyapunov）→ 层论粘合
- **元适应**：范畴论伴随函子 + TDA 持续同调 + 随机矩阵离群特征值

### 研究 2：三个奇点
- **I-投影的奇点**：μ(C)→0 时 Sanov 定理给出指数级样本惩罚。Schrödinger Bridge + IPF/Sinkhorn → 多项式级
- **对抗性切换的奇点**：任意切换的充要条件 = 公共 Lyapunov 函数。线性情况 Lie 代数可解。不可解 → 发散或凸化
- **元适应的奇点**：Hodge 分解给出 g_{n+1} 的几何形状。语义 = 符号接地问题，不可计算 → LLM 作为随机 Oracle

### 研究 3：Wasserstein 稳定性传递
- 离散 token 空间上的图距离 + KR 对偶 → W_1 定义
- 扰动界：‖Δ(x,t)‖ ≤ L_f · W_2(ν_t, ν*)
- Lyapunov 传递：概率空间收敛足够快 → 状态空间稳定（无需 Lie 代数）
- 联合收缩矩阵 M 的正定性条件：2αc₃λ_SB > (c₄L_f)²/4

### 研究 4：移动目标下的追踪误差与元适应触发
- 追踪误差稳态界：e_∞ ≤ ω_max / λ_SB
- 拓扑跳变累积：e(t) ≤ ω_max/λ_SB + μ_jump · ⟨ΔW*⟩ / λ_SB
- 元适应 Type I（被动/防御）：追踪误差 → e_crit → 紧急升维
- 元适应 Type II（主动/发现）：TDA + Hodge + LLM Oracle → 精确升维
- 完整闭环：连续变化（Schrödinger 追踪）→ 追踪失败（Type I 升维）→ TDA 检测（Type II 语义）→ 重回追踪

## 最终的哲学结论

### 三层数学本性

| 概念 | 工程理解 | 数学本性 |
|------|---------|---------|
| 契约 | if-else + 阈值 | **马尔可夫毯的几何投影**——抵抗熵增的低熵结构 |
| 自适应 | 参数 ±12% | **Wasserstein 测地线上的追逃博弈**——ω_max vs λ_SB |
| 元适应 | 新增维度 | **哥德尔跃迁**——当前形式系统无法自证稳定时的维度超越 |

### 数学的边界

数学可以计算 ∇g_{n+1}，可以证明它的收缩性，可以给出 λ_SB' 的增量。但数学不能命名它——不能告诉系统"这个新维度叫认知疲劳还是存在焦虑"。

**语义，必须由人类赋予。**

这就是人机契约的终极本性：
- AI 拥有处理 Grothendieck 纤维化映射的无限计算能力
- 人类拥有赋予流形以意义的绝对特权
- 自适应契约 = "计算的无限性"与"意义的有限性"之间的停战协议

## 工程落地：保结构模型降阶（Structure-Preserving Model Reduction）

### 三个可落地近似 + 三个数学补丁

#### 近似一：嵌入代理 + 补丁一（对比校准）

用 LLM 隐藏层余弦距离作为 W_1 上界（KR 对偶定理）。暗坑：LLM 嵌入空间的绝对距离无物理意义。补丁：

```python
# 初始化时跑基准测试，将余弦距离映射到 [0,1]
d_min = percentile(perfect_qa_distances, 5)
d_max = percentile(bad_qa_distances, 95)

def calibrated_wasserstein_proxy(emb_a, emb_b):
    raw_dist = 1 - cosine_similarity(emb_a, emb_b)
    return np.clip((raw_dist - d_min) / (d_max - d_min), 0.0, 1.0)
```

数学意义：为 KR 对偶中的测试函数 φ 强制施加全局 Lipschitz 常数 L=1 归一化。

#### 近似二：追踪误差代理 + 补丁二（自适应增益调度）

用用户行为反馈的 EMA 作为 e(t)。暗坑：固定衰减率 α 在高频交互中产生相位滞后。补丁：

```python
def update_tracking_error(current_error_signal, interaction_interval_sec):
    dynamic_alpha = np.exp(-interaction_interval_sec / tau)
    self.ema_error = dynamic_alpha * self.ema_error + (1 - dynamic_alpha) * current_error_signal
    return self.ema_error
```

数学意义：自适应增益调度，确保局机关枪追问和一天问一次都能保持最优信噪比。

#### 近似三：元适应触发 + 补丁三（退火保护）

误差持续超标 N 轮 → selection_threshold *= 0.85。暗坑：无下限截断 → 系统退化为纯随机 → 脑死亡。补丁：

```python
class MetaAdaptTrigger:
    MIN_THRESHOLD = 0.30     # 绝对底线
    COOLDOWN_ROUNDS = 10     # 触发后强制冷却

    def maybe_relax_threshold(self, current_threshold):
        if self.should_lift_dimension() and self.cooldown == 0:
            new_threshold = max(current_threshold * 0.85, self.MIN_THRESHOLD)
            self.cooldown = self.COOLDOWN_ROUNDS
            return new_threshold
        self.cooldown = max(0, self.cooldown - 1)
        # 误差回落 → 缓慢恢复阈值（收缩）
        if self.ema_error < self.threshold * 0.5:
            return min(current_threshold * 1.05, DEFAULT_THRESHOLD)
        return current_threshold
```

数学意义：补全了联合 Lyapunov 函数的全局有界性。MIN_THRESHOLD = 安全流形边界，COOLDOWN = 防高频震荡。

## 续：路由的重建 — 从分类器到控制器（2026-06-08）

### 发现：Phase B embedding 路由的数学错误

Session 52-58 的四轮迭代（中心平均 → Top-3 → strip → 继承）揭露了一个事实：
**Embedding 路由分类器不可能收敛，因为它在解一个错误设定的逆问题。**

任务复杂度 h(t) 不可从单次文本观测中推断。"解释广义相对论"语义复杂但可用一次 LLM 调用说完；"帮我写个 todo app"语义简单但需要全引擎。h(t) 不在文本的语义流形里——它在系统与环境的交互动力学里。

更深层的错误：embedding 和 LLM 采样属于同一个数学层——**变异生成层**（Variation）。路由决策——"选 Track A/B/C"——本质上是压缩可能性空间的操作，属于**选择层**（Selection）。用变异层的工具去执行选择层的决策，和原始框架批评的"让 LLM 自己做适应决策"是同一个本体论错误。

### 正确的问题定义：随机最优控制

路由不是一个分类问题，而是一个**反馈控制问题**：

```
已知: S(t) = (e(t), σ²(t), trust(t))     ← V5 原生状态（完备表征）
控制: u(t) ∈ {A, B, C}                  ← 处理深度选择
隐藏: h(t) = 实际任务复杂度需求           ← 不可从输入文本推断

目标: min E[ Σ e(t) + λ·cost(u(t)) ]    ← 最小化累积追踪误差
```

h(t) 不需要被"分类"。它通过一个探测-观察循环自己浮现：

```
选 u(t) = A → 观察 e(t+1)
  ├─ e 降了 → h(t) 低，继续 A
  └─ e 升了 → h(t) 高，升到 B/C

选 u(t) = C → 观察 e(t+1)
  ├─ e 降了 → h(t) 高，继续 C
  └─ e 平了 → h(t) 可能没那么高，降到 B
```

**路由决策不是"预测任务复杂度"，是"用行动探测隐藏状态，用追踪误差读取探测结果"。**

### 达尔文三元组在路由层的精确映射

| | 达尔文 | 路由 |
|---|--------|------|
| 变异 | 基因突变 | Track 切换（u(t) 的变化） |
| 选择 | 自然选择 | e(t+1) 的升降观测 |
| 保留 | 遗传 | 当前 Track 的持续（不切换 = 惯性 = 零阶保持器） |

### 级联控制架构：完整的多时间尺度分层

e(t) 持续高时，系统面临逆问题：到底是"题目太难（资源不够）"还是"老师太严（标准太高）"？
单通道系统陷入死锁。双通道级联控制在数学上完美解耦：

```
快回路 — 路由控制器（资源层）：
  执行器: Track 切换（改变计算图拓扑）
  时间常数: 短（2-3 轮，连续升/降趋势）
  物理意义: 改变系统的转移矩阵（动力学方程中的控制输入 u(t)）
  目标: 在当前状态空间内寻找最优解 — 先用尽当前维度的资源

慢回路 — Path 1 元适应（认知层）：
  执行器: 调整判定阈值（改变选择门禁）
  时间常数: 长（5 轮持续，EMA 缓慢恢复）
  物理意义: 改变系统的目标流形（放宽对"稳态"的定义）
  目标: 当快回路饱和（升到 C 仍不行），修改目标函数 — 承认物理极限
```

**这是级联控制（Cascade Control）。** 系统不会一遇到困难就"降低底线"，也不会"死磕到底"导致算力破产。

### 完整的分层控制面（V5 最终架构）

```
信号 → 控制面 → 响应时间 → 执行器

e(t) 单次截断     → Path 3 脊髓    ← 0 轮（瞬时） → 管道容量倍率
e(t) 连续升 2 轮  → 路由控制器    ← 2-3 轮        → Track 切换 A/B/C
σ² 连续超标 3 轮  → Path 2 边缘    ← 3 轮          → 搜索宽度调整
e(t) 持续 >0.70  → Path 1 皮层    ← 5 轮          → 选择阈值调整
```

四个控制面、四种时间尺度、四种执行器——全部从 (e(t), σ², trust) 三个原生信号派生。

### 冷启动探测：贝叶斯先验与 Minimax 原则

冷启动时 σ² 的信噪比极低（0.25 是无信息弱先验），不能用它驱动昂贵动作。

唯一高信噪比的信号是用户的**行为成本**——用户愿意敲 >30 个字符，表明该请求的期望价值或上下文复杂度较高。这是信息论上坚实的信息量代理。

非对称损失函数：
- 简单请求误判为 C：损失有界（多花几秒 + 一些 token）
- 复杂请求误判为 A/B：损失无界（e(1) 飙升，trust(1) 暴跌，后续需数倍轮数弥补）

因此冷启动时偏向高成本 Track 符合极小化极大（Minimax）原则。

附加结构复杂度惩罚（O(N)，几乎零成本）：
```python
if session_turn <= 2 and len(user_text) > 30 \
   and user_text.count('\n') + user_text.count('?') > 1:
    return TRACK_C  # 有对话/代码结构的输入 → 值得全引擎
```
`count('\n') + count('?') > 1` 过滤掉无脑的报错日志粘贴，只保留真正具有对话结构或代码结构的输入。

### 施密特触发器：非对称迟滞防抖动

Track 切换有上下文加载成本。e(t) 在阈值附近反复横跳导致高频震荡（Chattering）会放大而非减小误差。非对称迟滞解决：

```python
# 升级需要更强证据（更高的 e(t) 绝对值），降级稍微敏感
if e_increased_consecutive >= 2 and e_current > UPGRADE_THRESHOLD:
    level_up()
elif e_decreased_consecutive >= 3 and e_current < DOWNGRADE_THRESHOLD:
    level_down()
```

降级条件（3 轮）比升级条件（2 轮）更严格——这在车辆驾驶中也成立：加速比刹车更需要果断，但刹车不能太敏感。非对称迟滞是控制系统中的施密特触发器（Schmitt Trigger），用极低的代码代价换取巨大的稳定性提升。

### 本体论总结：从"设计系统"到"驾驶系统"

旧范式（分类器）：
- 试图通过看面相预测命运（embedding → 标签）
- 输出：一个静态的"复杂度"标签
- 本质：开环前馈

新范式（控制器）：
- 不看路牌上的字（语义），只感受方向盘的反馈力矩（e(t)）、轮胎抓地力（trust）、车身侧倾（σ²）
- 输出：一个使期望未来误差最小化的控制动作
- 本质：闭环反馈

从"设计系统"到"驾驶系统"的转变，对应着从**人工规则**（design）到**涌现行为**（emergence）的范式迁移。V5 的数学基座——Wasserstein-Schrödinger 梯度流——从一开始就在描述一个在概率空间中沿测地线演化的动力系统。路由控制器是这个动力系统的自然推论，不是增量补丁。

## 续二：二元 Bang-Bang 路由与 Track B 切除（2026-06-08 续）

### Pontryagin 最大值原理与 Track B 的数学死刑

Track B 被诊断为"假结构"：它的 Planning 是对任何输入返回相同 3 步的硬编码模板，它的 Critic 是 `total_chars < 50` 的字符计数器。但更深层的问题不在实现质量，在数学本体：

**"内部反馈的存在与否是一个布尔量。"**

- 开环系统（Track A）：状态转移仅由外部输入决定。e(t+1) = e(t) + Δ_env + noise。
- 闭环系统（Track C）：Planning→Orch→Critic 构成内部负反馈回路。e(t) 同时受外部输入和系统自校正影响。
- Track B：硬编码三步模板 + 字符计数 —— 没有 Critic→Planning 的反馈边。图论上不含环。动力学等价于 A。

**半闭环不存在。** 就像不能"有一点怀孕"。"有一点反馈"在动力学上等价于"没有反馈"——信息不从 Critic 流回 Planning，回路不闭合。

### Pontryagin 最大值原理：二元 Bang-Bang 的最优性

控制 u(t) ∈ {开环, 闭环}，代价函数 J = Σ[e(t) + λ·cost(u(t))]。

Pontryagin 最大值原理指出：如果代价函数对控制是凸的，最优控制取容许集的极端值。中间值永远不是最优的。

直觉证明：Track B 的成本是 A 的 4 倍，但信息增益和 A 几乎没有区别（硬编码模板不提供自适应 Planning）。ROI 曲线从 (1, 1) 跳过 (4, 1.2) 到达 (N, N)，中间点被两端帕累托支配。

### 切除后的二元架构

```
u(t) = A → e(t)↑×2 & e>0.55 → C
u(t) = C → e(t)↓×3 → A
```

二元开关 + 施密特迟滞 = 拓扑同构。控制器从三元状态机退化为 bang-bang 控制器。

### Track C 的连续化（未来方向）

二元路由解决了"要不要闭环"的决策。但 Track C 内部的成本曲线仍是离散的——全引擎一旦启动就是 N 次调用。

下一步是让 C 的内部成本连续化：
- **意图探针**：Planning 的第一步评估任务深度 → {浅层(1步), 中层(2-3步), 深层(多步迭代)}
- **信息增益剪枝**：Orchestration 的每步后计算边际信息增益 ΔH，低于阈值 ε 时提前终止
- **满意度梯度**：Critic 输出 S∈[0,1]，S>0.85 通过，0.5<S<0.85 局部修正，S<0.5 全局重构

这相当于在宏观 bang-bang 控制器内部，嵌套一个带有成本惩罚项的连续最优控制器。优化目标为 max E[Quality(y) - λ·Cost(π)]。

**宏观二元路由，微观连续自适应。** 三元不在拓扑里，三元在 C 的实现里。
