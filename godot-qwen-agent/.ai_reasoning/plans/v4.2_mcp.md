## 目标

让 Track B/C 的 `step["tool"]` 真正执行 MCP 工具，受 ActionPipeline 门控。

Demo 剧本：

## 三层改动

### 第 1 层：启动 MCP 服务器 + 注册工具 — `core/container.py`

在 Container init 时，根据配置启动 MCP 服务器并注册工具。

```python
# 新增 config 字段: mcp_servers (list of MCP server configs)
# 启动时调用 register_mcp_server(cfg) → 发现工具 → COMPONENT_REGISTRY.register("tool", name, cls)
```

新增 `Config.mcp_servers` 字段，默认值 `[]`。加上 `--mcp` 命令行参数。

### 第 2 层：工具执行接入 Track B/C — `core/repl.py` + `core/track_c.py`

`_track_b_agentic()` 和 `TrackCEngine.run()` 中，step 有 `tool` 字段时 → 调用 `ToolAdapter.execute()`。

```python
# 当前: 只做 knowledge_search 门控, LLM 自由发挥
# 改为: ToolAdapter.from_llm_response() → ActionPipeline.check() → ToolAdapter.execute()
```

### 第 3 层：MCP 工具注册表（可选）

`core/contracts/v3_protocols.py` 的 `ToolRegistry` Protocol 加上 MCP 实现，或者直接用现有的 `COMPONENT_REGISTRY`（已支持 `"tool"` 类型）。

## 风险

- **MCP 依赖**: 需要 `pip install mcp`。`mcp_adapter.py` 已经 import 了它。
- **stdio 通信**: MCP 服务器通过 stdio 启动，Windows 兼容性需验证。
- **事件循环**: MCP 客户端是 async，需在 `safe_async_run()` 中运行。
