```python
class HarnessToolRegistry:
    def get_match_patterns(self, name: str) -> tuple[str, ...]:
        try:
            cls = self._registry.get("tool", name)
            return getattr(cls, "match_patterns", ())
        except KeyError:
            return ()

    def extract_params(self, name: str, user_text: str) -> dict:
        try:
            cls = self._registry.get("tool", name)
            fn = getattr(cls, "extract_params", None)
            if callable(fn):
                return fn(user_text)
        except KeyError:
            pass
        return {}
```

#### 5. `mainboard/orchestrate/harness.py` — _resolve_tools 规则优先

```python
import re

def _resolve_tools_deterministic(user_text: str, registry) -> tuple | None:
    """规则引擎 — 100% 确定，零延迟。"""
    for tool_name in registry.list_tools():
        for pattern in registry.get_match_patterns(tool_name):
            if re.search(pattern, user_text):
                params = registry.extract_params(tool_name, user_text)
                return ({"tool": tool_name, "params": params},)
    return None

class Harness:
    async def _resolve_tools(self, user_text, policy):
        if hasattr(self.tool, 'registry'):
            result = _resolve_tools_deterministic(user_text, self.tool.registry)
            if result:
                return result
        # LLM 兜底
        return await self._llm_resolve_tools(user_text, policy)
```

## 一、问题诊断

当前 V9 Harness 有三个并行的"注册表"，互不相通：

```
COMPONENT_REGISTRY (core层)       MockToolRegistry (v9_cli.py)      llm_bridge._prompts (硬编码)
├── write_file ✅                 ├── write_file (唯一)              ├── planning (中文)
├── read_file ✅                  └── 其他: 全部缺失                 ├── synthesis
├── run_powershell ✅                                                 ├── critic
├── web_search ✅                                                     └── tool_resolver
├── sandbox_python ✅
└── ... 更多
         ↑                                    ↑                            ↑
    ToolBridge 不查这里                  ToolBridge 查这里             LLMBridge 只查这里
    (不同协议)                          (get_metadata/get_executor)   (dict lookup)
```

**根因：Harness 层缺一套统一的插件协议。** 内核不感知这个缺口（内核只管"该不该走工具路径"），但 Harness 执行层需要知道"有哪些工具可用"。

## 三、协议版本化

### 版本常量

```python
# harness/plugin_protocol.py
PROTOCOL_VERSION = "9.2.0"
```

### 兼容性规则

| 版本差 | 行为 | 含义 |
|--------|------|------|
| Major 不同 (9.x vs 10.x) | **拒绝挂载** | 协议 API 断裂 |
| Minor 不同 (9.2 vs 9.3) | **挂载 + 能力协商** 🔴 | 接口形状兼容，但新语义需显式检查 `capabilities` |
| Patch 不同 | **静默通过** | 完全向后兼容 |

### 🔴 能力协商层（红队修正 #6）

Minor 版本兼容的致命漏洞：版本号只保证**接口形状**兼容，不保证**语义契约**兼容。V9.2 插件挂载到 V9.3 Harness 时，对 V9.3 新增的语义完全无知。

**修正：插件必须显式声明自己支持哪些可选能力。Harness 调用前必须检查。**

```python
# 插件侧 — 声明能力
class MyTool:
    metadata = PluginManifest(
        name="write_file",
        slot_type="tool",
        protocol_version="9.2.0",
        capabilities=frozenset({"dry_run", "batch_execute"}),
    )

# Harness 侧 — 调用前检查，显式 fallback
if registry.has_capability("write_file", "dry_run"):
    preview = await tool.dry_run(params)
else:
    logger.info("write_file 不支持 dry_run，跳过预览")
    preview = None  # 确定性 fallback，而非 AttributeError
```

**Mount-time 行为：**
- 必须能力（Protocol 定义的方法）：缺失 → **拒绝挂载**
- 可选能力（`capabilities` frozenset 中声明的）：不声明 → 不拒绝，但 `registry.has_capability()` 返回 `False`
- 可选能力（声明了但缺失扩展 Protocol）：**拒绝挂载**（声明了就必须提供）

这解决了 Minor bump 从"假设兼容 → 警告"升级为"精确知道缺什么 → 确定性 fallback"。

### 插件清单（每个插件必须携带）

### 5.1 PluginRegistry

```python
class PluginRegistry:
    """统一插件注册表。Tool 槽委托给 COMPONENT_REGISTRY（桥接），其余自管。"""

    def __init__(self):
        self._slots: dict[str, dict[str, Any]] = {}
        self._frozen = False
        # 🔴 红队修正 #6：追踪缺失的可选能力
        # {"tool/write_file": {"dry_run", "streaming"}, ...}
        self._missing_capabilities: dict[str, set[str]] = {}

    def register(self, slot_type: str, name: str, plugin: Any) -> None:
        validate_slot(slot_type, plugin)       # 挂载时校验（含能力检查）
        self._slots.setdefault(slot_type, {})[name] = plugin

    def get(self, slot_type: str, name: str) -> Any: ...
    def list_slots(self, slot_type: str) -> list[str]: ...
    def freeze(self) -> None: ...

    # 🔴 能力协商 API
    def has_capability(self, name: str, capability: str) -> bool:
        """调用方在调用可选能力前必须查询此方法。
        True → 可以调用，False → 使用确定性 fallback。

        key = f"{slot_type}/{name}"  # 内部追踪键

    def missing_capabilities(self, name: str) -> frozenset[str]:
        """返回某插件缺失的所有可选能力。用于诊断。"""
        return frozenset(self._missing_capabilities.get(name, set()))

    def get_tool_adapter(self) -> "HarnessToolRegistry": ...
```

### 5.2 HarnessToolRegistry — 关键桥接（🔴 红队修正版）

把 `COMPONENT_REGISTRY` 的工具类翻译为 `ToolBridge` 期望的接口：

```
COMPONENT_REGISTRY                   HarnessToolRegistry                ToolBridge
─────────────────                   ───────────────────                ──────────
register("tool", name, cls)   →     get_metadata(name) → ToolMetadata   registry.get_metadata(name)
cls.VERSION: SemVer                 get_executor(name)  → wrapper       registry.get_executor(name)
cls.execute(**named)                wrapper.execute(dict, token)→str    await executor.execute(params)
  → ToolResult(success,data,error)    ↑ 结构化 JSON                    ↑ 工具超时时 cancel
```

**四个翻译（红队修正后）：**

| 差异 | 旧工具 | ToolBridge 期望 | 适配方式 |
|------|--------|----------------|---------|
| 类型 | 类（需实例化） | 实例 | `stateless=True` → 每次 `cls()`；`stateless=False` → 单例缓存 |
| 同步/异步 | `def execute(...)` 同步 | `async def execute(params, token)` | `asyncio.to_thread(...)` + 🔴 `cancellation_token` |
| 返回值 | `ToolResult(success, data, error)` | JSON `str` | 🔴 结构化 JSON：`{"status":"ok","data":...}` / `{"status":"error","code":...,"message":...}` |
| 取消安全 | 无取消机制 | 超时/用户中断 → `CancelledError` | 🔴 `threading.Event` token 注入，取消时 set → 等待线程退出 |

```python
import asyncio, json, threading, time, logging
from core.contracts.registry import COMPONENT_REGISTRY

logger = logging.getLogger(__name__)

class HarnessToolRegistry:
    """把 COMPONENT_REGISTRY 的工具类翻译为 ToolBridge 期望的接口。"""

    def __init__(self):
        self._core = COMPONENT_REGISTRY
        self._instances: dict[str, object] = {}  # 🔴 stateless=False 的单例缓存

    def get_metadata(self, name: str) -> ToolMetadata | None:
        try:
            cls = self._core.get("tool", name)
        except KeyError:
            return None
        manifest = getattr(cls, 'PLUGIN_MANIFEST', None)
        return ToolMetadata(
            name=name,
            description=getattr(cls, 'description', ''),
            timeout_ms=getattr(cls, 'TIMEOUT_MS', 10000),
            required_params=_extract_params(cls.execute),
            # 🔴 红队修正 #4: 有状态工具声明
            stateless=getattr(manifest, 'stateless', True) if manifest else True,
            # 🔴 红队修正 #2: 取消支持声明
            cancellable=getattr(manifest, 'cancellable', True) if manifest else True,
        )

    def get_executor(self, name: str):
        cls = self._core.get("tool", name)
        manifest = getattr(cls, 'PLUGIN_MANIFEST', None)
        stateless = getattr(manifest, 'stateless', True) if manifest else True

        if not stateless:
            # 🔴 有状态工具：单例缓存
            if name not in self._instances:
                self._instances[name] = cls()
            instance = self._instances[name]
        else:
            instance = cls()
        return _ToolWrapper(instance, name, stateless=stateless)


class _ToolWrapper:
    """包装旧工具为 ToolBridge 兼容接口。

    🔴 红队修正 #2: 注入 threading.Event 作为取消令牌。
    🔴 红队修正 #3: payload 是 JSON 结构化字符串，非自由文本。
    """

    def __init__(self, instance, name: str, stateless: bool = True):
        self._inst = instance
        self._name = name
        self._stateless = stateless
        self._cancellable = getattr(
            getattr(instance, 'PLUGIN_MANIFEST', None), 'cancellable', True
        )

    async def execute(self, params: dict) -> str:
        import asyncio

        # 🔴 创建取消令牌
        token = threading.Event()
        task = asyncio.current_task()

        def _run_with_token():
            # 注入 token 到 params（如果工具支持）
            if self._cancellable:
                params_with_token = {**params, "cancellation_token": token}
            else:
                params_with_token = params
            try:
                return self._inst.execute(**params_with_token)
            except Exception as e:
                logger.exception(f"[{self._name}] 工具执行异常")
                return type('ToolResult', (), {
                    'success': False, 'data': None,
                    'error': f"{type(e).__name__}: {e}",
                })()

        try:
            result = await asyncio.to_thread(_run_with_token)
        except asyncio.CancelledError:
            # 🔴 取消信号 → 通知线程退出
            token.set()
            logger.warning(f"[{self._name}] 收到取消信号，等待线程退出...")
            # 等待线程自然退出（带超时，最多等 5 秒）
            # 注意：asyncio.to_thread 不返回线程句柄，这里用 Event 作协程间信号
            # 实际实现中需维护线程引用。此处为设计文档伪代码。
            raise  # 重抛给 ToolBridge 的超时处理

        # 🔴 红队修正 #3: 结构化 JSON payload
        return _serialize_tool_result(result, self._name)


def _serialize_tool_result(result, tool_name: str) -> str:
    """将 ToolResult 序列化为结构化 JSON 字符串。

    Critic 可以可靠地 json.loads(payload) 解析，无需正则匹配。
    Telemetry Bus 直接从原始 ToolResult 采集，不经过此函数。
    """
    if getattr(result, 'success', False):
        data = getattr(result, 'data', None)
        return json.dumps({
            "status": "ok",
            "tool": tool_name,
            "data": str(data) if data is not None else None,
        }, ensure_ascii=False)
    else:
        error_msg = getattr(result, 'error', 'Unknown error')
        error_code = getattr(result, 'error_code', 'UNKNOWN')
        return json.dumps({
            "status": "error",
            "tool": tool_name,
            "code": error_code,
            "message": str(error_msg),
        }, ensure_ascii=False)


def _extract_params(execute_fn) -> tuple[str, ...]:
    """从 execute 函数签名提取参数名（排除 self 和 cancellation_token）。"""
    import inspect
    try:
        sig = inspect.signature(execute_fn)
        return tuple(
            p for p in sig.parameters
            if p not in ('self', 'cancellation_token')
        )
    except (ValueError, TypeError):
        return ()
```

## 六、自动发现（🔴 红队修正 #1：消除导入副作用）

### 6.1 设计原则

**Python `importlib.import_module` 会立即执行目标文件的全部顶层代码。** 如果插件文件中有顶层 I/O、网络连接、或对未初始化总线的引用，将在 `plugin_registry.freeze()` 之前触发不可控副作用。更致命的：如果插件 A 导入了 Harness 核心模块，而 Harness 核心又触发了发现流程 → **Circular Import 崩溃**。

修正后的三原则：
1. **生产环境用显式清单，不用目录扫描**
2. **目录扫描仅作开发 fallback，且只收集路径不执行导入**
3. **真正的 `import_module` 推迟到第一次 `registry.get()` 调用时（LazyPluginLoader）**

### 6.2 三层发现（修正版）

| 层 | 机制 | 何时执行导入 | 目标 |
|----|------|------------|------|
| **核心工具** | `COMPONENT_REGISTRY.auto_discover("components/tools")` → 遍历 `list_strategies("tool")` → 桥接到 PluginRegistry | 立即（已有机制，已验证安全） | write_file, read_file, run_powershell, web_search, sandbox_python |
| **Harness 插件（生产）** | 读取 `harness/plugins/manifest.json` → 仅加载清单中声明的模块 | **延迟** — 第一次 `registry.get(slot_type, name)` 时 | prompts, tracks, observers, events |
| **Harness 插件（开发）** | 扫描 `harness/plugins/{slot_type}/*.py` → 收集文件路径 → 返回 `LazyPluginLoader` | **延迟** — 同生产 | 开发模式快速迭代 |
| **显式注册** | `plugin_registry.register(slot_type, name, plugin)` | 调用时已导入 | MCP 动态工具、测试桩 |

### 6.4 LazyPluginLoader

```python
class LazyPluginLoader:
    """延迟导入包装器。持有模块路径和类名，在第一次访问时才 import。

    🔴 红队修正 #1: 消除发现阶段的导入副作用。
    """

    def __init__(self, module_path: str, class_name: str, slot_type: str, name: str):
        self._module_path = module_path
        self._class_name = class_name
        self._slot_type = slot_type
        self._name = name
        self._loaded: Any = None          # 缓存已加载的类/实例
        self._load_error: str | None = None

    def load(self) -> Any:
        """惰性加载。失败时记录警告并返回 None，绝不中断启动。"""
        if self._loaded is not None:
            return self._loaded
        if self._load_error is not None:
            return None
        try:
            import importlib
            module = importlib.import_module(self._module_path)
            self._loaded = getattr(module, self._class_name)
            return self._loaded
        except ImportError as e:
            self._load_error = str(e)
            logger.warning(
                f"插件加载失败: {self._slot_type}/{self._name} "
                f"({self._module_path}.{self._class_name}): {e}"
            )
            return None
        except Exception as e:
            self._load_error = f"{type(e).__name__}: {e}"
            logger.exception(
                f"插件加载异常: {self._slot_type}/{self._name}"
            )
            return None

    @property
    def is_loaded(self) -> bool:
        return self._loaded is not None

    @property
    def error(self) -> str | None:
        return self._load_error
```

### 6.5 发现函数

```python
def discover_from_manifest(plugin_registry: PluginRegistry, manifest_path: str = "harness/plugins/manifest.json") -> int:
    """从显式清单加载插件（生产环境默认）。

    只注册 LazyPluginLoader — 真正的 import 推迟到第一次 registry.get()。
    加载失败记录警告，绝不中断启动。
    """
    import json
    try:
        with open(manifest_path, 'r', encoding='utf-8') as f:
            manifest = json.load(f)
    except FileNotFoundError:
        logger.info(f"manifest.json 未找到: {manifest_path}，跳过 Harness 插件加载")
        return 0

    count = 0
    for slot_type, entries in manifest.get("plugins", {}).items():
        for name, spec in entries.items():
            loader = LazyPluginLoader(
                module_path=spec["module"],
                class_name=spec["class"],
                slot_type=slot_type,
                name=name,
            )
            plugin_registry.register_lazy(slot_type, name, loader)
            count += 1
    return count


def discover_harness_directory(plugin_registry: PluginRegistry, base_path: str = "harness/plugins") -> int:
    """开发模式：扫描目录，收集 LazyPluginLoader（不执行导入）。

    🔴 红队修正 #1: 只扫描文件系统收集路径，不调用 import_module。
    真正的导入推迟到第一次 registry.get()。
    """
    from pathlib import Path
    path = Path(base_path)
    if not path.exists():
        return 0

    count = 0
    for py_file in path.glob("*/*.py"):
        if py_file.name.startswith("_"):
            continue
        slot_type = py_file.parent.name  # e.g. "prompts" → strip 's' → "prompt"
        # Normalize slot_type: prompts → prompt, tracks → track, observers → observer, events → event
        slot_type = slot_type.rstrip('s')
        if slot_type not in ("tool", "prompt", "track", "observer", "event"):
            continue

        name = py_file.stem  # e.g. "planning_prompt"
        module_path = str(py_file.with_suffix('')).replace('/', '.').replace('\\', '.')
        # Heuristic class name: stem → PascalCase
        class_name = _stem_to_class_name(py_file.stem)

        loader = LazyPluginLoader(module_path, class_name, slot_type, name)
        plugin_registry.register_lazy(slot_type, name, loader)
        count += 1

    return count
```

## 七、validate_slot — 挂载时校验

```python
def validate_slot(slot_type: str, plugin: Any) -> None:
    protocol_map = {
        "tool": ToolSlot, "prompt": PromptSlot,
        "track": TrackSlot, "observer": ObserverSlot, "event": EventTypeSlot,
    }
    proto = protocol_map[slot_type]

    # 1. isinstance（runtime_checkable）
    if not isinstance(plugin, proto):
        raise TypeError(f"插件不符合 {slot_type} Protocol")

    # 2. 签名校验（方法参数名必须和 Protocol 一致）
    method = {"tool": "execute", "prompt": "build", "track": "run",
              "observer": "observe", "event": None}[slot_type]
    if method:
        proto_sig = inspect.signature(getattr(proto, method))
        impl_sig = inspect.signature(getattr(plugin, method))
        impl_params = [p for p in impl_sig.parameters if p != 'self']
        if list(proto_sig.parameters) != impl_params:
            raise TypeError(f"签名不匹配: 期望 {list(proto_sig.parameters)}, 实际 {impl_params}")

    # 3. metadata 完整性
    if not isinstance(plugin.metadata, PluginManifest):
        raise TypeError("缺少 PluginManifest")
    if plugin.metadata.slot_type != slot_type:
        raise ValueError(f"slot_type 不匹配")

    # 4. 协议版本检查
    _check_protocol_version(plugin.metadata.protocol_version, PROTOCOL_VERSION)

    # 🔴 红队修正 #5: 废弃方法检查
    if plugin.metadata.deprecated_methods:
        for method in plugin.metadata.deprecated_methods:
            logger.warning(
                f"插件 '{plugin.metadata.name}' 使用了废弃方法 '{method}'。"
                f"该方法将在下一 Major 版本中移除。"
                f"迁移指南: {plugin.metadata.migration_url or '未提供'}"
            )

    # 🔴 红队修正 #6: 能力协商检查
    # 1. 插件声明的 capabilities 必须实际实现了对应的扩展 Protocol
    # 2. 缺失的 capabilities 记录到 registry._missing_capabilities
    if plugin.metadata.capabilities:
        for cap in plugin.metadata.capabilities:
            extension_proto = _CAPABILITY_PROTOCOLS.get(cap)
            if extension_proto and not isinstance(plugin, extension_proto):
                # 声明了能力但没有实现 → 拒绝（虚假声明）
                raise TypeError(
                    f"插件 '{plugin.metadata.name}' 声明了能力 '{cap}' "
                    f"但未实现对应的扩展 Protocol {extension_proto.__name__}"
                )
            elif not extension_proto:
                # 未知能力（可能是未来版本的）→ 记录但允许挂载
                logger.debug(f"插件 '{plugin.metadata.name}' 声明了未知能力 '{cap}'")

    # 反向检查：扩展 Protocol 已知但插件未声明 → 记录到 _missing_capabilities
    required_caps = _get_required_capabilities_for_version(
        plugin.metadata.protocol_version, PROTOCOL_VERSION
    )
    for cap in required_caps:
        if cap not in plugin.metadata.capabilities:
            _record_missing(registry, plugin.metadata.name, cap)
```

## 十、关键设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 桥接 vs 重写 COMPONENT_REGISTRY | **桥接** | 旧工具 5+ 实现 + MCP 动态发现，重写破坏面太大 |
| 类 → 实例 | **stateless 字段决定** | 无状态工具每次 new，有状态工具（sandbox）单例缓存 |
| 同步 → 异步 | **asyncio.to_thread + 取消令牌** | 🔴 线程注入 `threading.Event`，取消时 set → 等线程退出 |
| ToolResult → str | **JSON 结构化** | 🔴 `{"status":"ok/error","code":...,"message":...}`，Critic 可靠解析 |
| 插件发现 | **manifest.json + LazyPluginLoader** | 🔴 消除导入副作用和循环依赖风险 |
| PluginRegistry 在 Harness 层 | **不进内核** | 铁律 3（零自然语言）+ 铁律 5（零动态分配） |
| 版本检查时机 | **挂载时** | 启动失败 > 运行时诡异行为 |
| freeze() 不可逆 | **设计如此** | 不变量 #23，测试用独立实例 |
| 废弃方法 | **Minor 兼容时打 warning + 迁移 URL** | 🔴 不静默通过，给插件作者明确的升级路径 |
| Minor 兼容性 | **版本号 + capabilities 双重协商** | 🔴🔴 版本号保接口形状，capabilities 保语义契约 |
