## 三刀切入（只做最有效的 3 项）

### 刀 1: 编排并行化 — `core/track_c.py` (10 行)

`_do_orchestrate()` 的 for 循环改为 `asyncio.gather`:

```python
async def _do_orchestrate_parallel(self, plan, user, system, prev_context):
    tasks = [self._orchestrate_one(step, user, system, prev_context) for step in plan]
    results = await asyncio.gather(*tasks, return_exceptions=True)
    return [r if isinstance(r, str) else f"[error: {r}]" for r in results]
```

**效果**: 7 步从 7×3=21 次顺序调用 → 并行执行, ~3 次调用的时间。

### 刀 2: Planning 减半 — `core/track_c.py` (5 行)

`_do_plan()` 中：如果 LLM 的合成步骤(synthesize)和分解步骤(decompose)是同一个模型, 合并 prompt:

```python
goal = f"{user}\n\n[约束: 直接输出 3-5 个 JSON 步骤, 不需要先分析再合成。一步完成。]"
```

**效果**: Planning 2 次 LLM → 1 次。

### 刀 3: 后端参数透传 — `core/adapters/cloudllm_backend.py` (3 行)

```python
def generate(self, prompt, context=None, **params):
    text = self._client.generate(prompt)  # TODO: pass params
```
改为:
```python
def generate(self, prompt, context=None, **params):
    text = self._client.generate(prompt, params.get("temperature"), params.get("max_tokens"))
```

**效果**: 引擎设置的 max_tokens=4096 不再被忽略 → 输出质量提升 + 可能更快。
