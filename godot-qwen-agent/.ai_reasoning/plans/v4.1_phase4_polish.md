## 问题 1: Track C 只拆 1 步

**根因:** `_do_plan()` 查找 `trace_context["planning.steps"]` 但引擎不设这个 key。
引擎的 StreamItem 用 `planning.step_index`, `planning.reasoning_depth` 等逐项元数据,
没有聚合的 `planning.steps` 列表。查不到 → fallback 到全文拼接 → 1 个合成步骤。

**修复（3 处）:**

### 1a. 修正 `_do_plan()` 提取逻辑 — `core/track_c.py`
不查 `planning.steps` key。改为:
- 收集所有 `is_terminal=False` 的 StreamItem, 按 `step_index` 分组
- 每组 = 一个 plan step
- 如果仍是 1 步 → 触发 retry prompt

### 1b. 步数不足时触发重试 — 同文件
`_do_plan()` 返回值若 len < 2:
- 发 "规划粒度过粗 → 重新规划" 的 emit
- 用更强的 prompt 重试一次: "请至少拆解为 3 个可独立执行的子任务，每个子任务包含 {prompt, tool} 字段。返回 JSON 数组。"

### 1c. Planning prompt 注入结构约束 — 不改引擎文件
`_do_plan()` 构建 `PlanningContext` 时, 把 `goal` 扩展:
```python
goal = f"{user}\n\n[约束: 必须拆解为至少 3 个独立子任务。每步包含 prompt 和 tool 字段。]"
```
不动 `engines/planning/llm.py`，只改调用方传入的 goal 字符串。

## 问题 2: 响应偏长（HIGH 模式 800+ 字符）

**根因:** OutputPipeline 用句子计数截断（HIGH=8 句），但中文 8 句轻松过 800 字。
且硬截断在句子边界，不是字符边界。

**修复（2 处）:**

### 2a. OutputPipeline 加字符上限 — `core/adapters/output_pipeline.py`
`_truncate_sentences()` 后追加字符截断:
```
HIGH:   max 800 chars (当前 8 句无上限 → 加 800 字硬顶)
MEDIUM: max 400 chars (当前 5 句)
LOW:    max 150 chars (当前 3 句)  
MINIMAL: max 60 chars  (当前 2 句)
```
字符截断: 找上限前最后一个 `。` `！` `？` `\n\n` 处截断。
不截在句子中间。

### 2b. System prompt 注入字数约束 — `core/repl.py` `_build_contract_directive()`
```
HIGH:    "总字数 600-800 字，多用列表，少用过渡句"
MEDIUM:  "总字数 300-400 字"
LOW:     "总字数 100-150 字，单段落"
MINIMAL: "一句话，不超过 50 字"
```
提示 + 管道双重约束。提示是"请求"，管道是"强制执行"。
