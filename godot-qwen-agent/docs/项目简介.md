# V9 Agent 操作系统 — 项目简介

## 一句话

从头设计并实现了一个五层微内核 Agent 操作系统，用 Linux 内核设计原则解决 AI Agent 的稳定性、可扩展性和确定性决策问题。

## 项目定位

这不是一个调参项目。这是一个**从零设计 Agent 底层架构**的工程。

当前 AI Agent 行业的主流做法是把 LLM 调用链串起来（LangChain / AutoGPT 模式）。V9 的做法是把 Agent 当作一个**操作系统**来设计：有内核层、主板层、总线矩阵、插件协议、安全仲裁器。每一层都有对标 Linux 子系统的设计决策。

## 技术架构

```
Layer 4: Observer     — 语义观察器（自然语言 → 结构化信号）
Layer 3: Mainboard    — 主板（总线矩阵 + 插件系统 + 编排器）
Layer 2: MPC Kernel   — 微内核（纯函数决策，零自然语言）
Layer 1: Protocol     — 冻结 ABI（跨层类型契约）
```

### 内核层 (MPC Kernel)

- **16 维状态向量**驱动决策：trust（信任）、e_t（跟踪误差）、context_depth（上下文深度）等
- **ODE 积分器**：帧率无关的信任动态演化（脉冲响应 + 连续松弛，三阶段 trust 恢复）
- **8 门 Bang-bang 路由链**：0 = 社交信号（最高优先级），1 = 信任危机，4 = 冷启动/模糊意图 → 工具调用，7 = 方差安全阀
- **安全仲裁器**：Lipschitz 梯度裁剪 + Hoyer 稀疏度判别，异常状态空间跃变时自动降级或熔断
- **铁律**：内核不碰自然语言、不动态分配、纯函数边界、梯度有界、信息损失可审计

### 主板层 (Mainboard)

- **四条总线**对标硬件：
  - LLM Bus (AHB 级) — LLM 调用：地址解码 + 协议翻译 + MAC 重试 + 超时降级
  - Tool Bus (APB 级) — 工具调用：信号量限流(5) + 超时 + 跨总线事件转发
  - Event Bus (NVIC 级) — 中断脉冲：优先级仲裁 + Lamport 逻辑时钟 + 等效合并
  - Telemetry Bus (CoreSight 级) — (s,a,r) 三元组异步 JSONL 写入
- **三层插件协议**：L2(策略) / L3(工具+提示词+Track) / L4(观察器)，每层独立 slots/ + manifest.json
- **PluginRegistry**：挂载时校验（isinstance Protocol + 签名检查 + 版本协商 + 能力声明）、启动后冻结（不可逆）
- **规则引擎**：确定性工具匹配（正则碰撞，0ms 延迟）→ LLM 兜底（处理未知意图）。消除了 100% LLM 匹配时 ~25% 的空列表幻觉
- **总线宪法**：中断优先级表 NMI 槽位(0,1) 物理锁定，插件不可染指（防止优先级反转）

### 消除的硬编码（V9.2b 核心战役）

| 硬编码 | 原位置 | 修复方案 |
|--------|--------|---------|
| 4 个中文提示词 | `llm_bridge._prompts` | CorePromptBundle 插件（Bundle 模式） |
| 9 个事件优先级 | `event_bridge.PRIORITY` | 总线宪法 + NMI 物理锁 + freeze |
| Track C 默认构造 | `harness.py:90` | 两阶段点火（inject_context 依赖注入） |
| Mock 工具注册 | `app.py` / `v9_cli.py` | HarnessToolRegistry 桥接 COMPONENT_REGISTRY |
| Observer 硬编码 | `app.py:90` | PluginManifest 属性注入 + get_instance() |
| P4 冷启动轮数限制 | `route_controller.py` | 移除 round_count <= 2（Agent 终身拥有工具调用能力） |

### 关键 Bug 修复

- **Lipschitz 基线修正**：长时间 LLM 调用（7s）→ 大 dt → ODE 漂移积累 → 安全仲裁器误判 WAIT。将 delta 比较基线从 `prev_raw_state_vector` 改为 `prev_state_vector`，排除 ODE 时间漂移（delta: 1.53 → 0.12）
- **KernelEvent 字段统一**：消除 protocol 与 event_bus 之间的重复定义和字段名不一致
- **LLM 幻觉参数过滤**：`_ToolWrapper._filter_params()` 用真实函数签名过滤 LLM 生成的幻觉参数

## 与典型 AI 项目的区别

| 典型 Agent 项目 | V9 |
|----------------|-----|
| LLM 调用链串联 | 五层微内核架构 |
| prompt 硬编码在代码里 | 插件化 Bundle，热替换 |
| 工具注册靠手动 import | 三层 manifest.json 自动发现 + 延迟加载 |
| 路由决策靠 LLM（~2s） | 8-gate 纯函数路由（<1μs） |
| 崩溃后无恢复机制 | ODE 信任衰减 + 安全仲裁器自动恢复 |
| 第三方工具无隔离 | PluginRegistry freeze 锁 + 沙盒防御 |
