## 核心公式 1：帧率无关 ODE 演化

### 连续形式

```
ds/dt = -α·(s - s_target) + β·δ(t - t_event)
  ↑            ↑                    ↑
状态变化    EMA 弛豫（平滑）    脉冲响应（事件触发）
```

### 离散化形式（实际代码中的形式）

```
s_{t+1} = s_t + (1 - exp(-dt/τ)) · (s_target - s_t) + β · I_event
```

**面试一句话**："我的内核用 `1-exp(-dt/τ)` 做状态演化——无论调用间隔是 1ms 还是 1s，动力学行为不变。所以同一套内核能同时驱动对话 Agent 和机器人。"

**完整推导见**：[V5-V6 backplane 一、V5 数学基座 — 保结构模型降阶 第 3 近似](../docs/V5-V6-mathematical-backplane.md)

**协作者阅读深度**：

| 方向 | 需要理解到什么程度 |
|------|-----------------|
| RL | **物理意义层** — 理解为什么帧率无关对 RL 训练数据的一致性至关重要（不同传感器频率不破坏训练分布） |
| 感知 | **接口层** — 理解 ODE 只演化 `ode_` 前缀维度，Observer 不碰这些维度 |
| 控制 | **安全边界层** — 理解 τ 的选择对响应速度的影响：τ 越小响应越快，但越容易被噪声触发 |

## 核心公式 2：乘法门控替代加法耦合

### 公式

```
Critic: θ = θ₀ - α · f_drift(d) · g(e_t)

惩罚项 = α · f(drift) · g(e_t)     ← 乘法！
        NOT: α · (f(drift) + g(e_t)) ← 这是错的
```

**面试一句话**："两个独立风险源的惩罚必须相乘。如果 drift 风险为 0（语义很稳定），整个惩罚就是 0——不会因为另一维度（e_t）高而误降标准。"

**完整推导见**：[V5-V6 backplane 二、Critic 乘法门控](../docs/V5-V6-mathematical-backplane.md) + [CLAUDE.md 不变式 #46](../CLAUDE.md)（乘法门控，永不加法耦合）

**为什么加法是错的**：

```
场景：用户切换了话题（drift 高），但输出质量很好（e_t 低）
加法耦合：惩罚 = α·(f(高) + g(低)) = 仍然有惩罚 → 错误降级
乘法耦合：惩罚 = α·f(高)·g(低) = 惩罚趋近 0 → 正确，不降级
```

**协作者阅读深度**：

| 方向 | 需要理解到什么程度 |
|------|-----------------|
| RL | **物理意义层** — 理解乘法门控的设计哲学：独立风险源不应互相污染。这对 RL 的 reward shaping 有直接启发 |
| 控制 | **安全边界层** — 理解为什么乘法保证"任一因子归零则惩罚归零"——这防止了传感器故障（单维跳变）触发全局降级 |
| 感知 | **接口层** — 你提供的特征质量（drift, clarity）通过乘法门控影响决策——理解这个链路有助于你设计更好的特征 |

## 核心公式 3：连续→离散映射的拓扑同态

### 概念

```
连续控制面 C ⊂ ℝ⁴ (drift, clarity, trust, e(t))
              ↓ 量化映射 φ
离散行为空间 D = {GENERATE, TOOL, WAIT, CLARIFY, YIELD, STOP, MOVE, ...}

同态度量 = |{ (c₁,c₂) 在 C 中相邻 → φ(c₁) 和 φ(c₂) 在 D 中相同或相邻 }|
           ──────────────────────────────────────────────────────────
                          |C 中所有相邻对的总数|

当前 ≥ 50%，目标 ≥ 65% (V8.0)
```

**面试一句话**："从连续数学到离散动作的映射，我用拓扑同态度量来保证'相邻的连续状态产生相似的离散行为'——当前 50%，学术界尚无同类度量。"

**完整推导见**：[CLAUDE.md 不变式 #63](../CLAUDE.md) + [V5-V6 backplane 七、V7 拓扑同态](../docs/V5-V6-mathematical-backplane.md)

**量化债务表（当前状态）**：

| 变量 | 值域 | 行为状态数 | 债务 |
|------|------|----------|------|
| trust | [0,1] | 6 | [0.30, 0.55) — 0.25 span, 零行为差异 |
| e(t) | [0,1] | 4 | [0, 0.55] — 平凡信号对路由不可见 |
| clarity | [0,1] | 5 | [0.35, 0.70] — 正常范围无 prompt 效果 |
| drift | [0,1] | 4 | — |

**协作者阅读深度**：

| 方向 | 需要理解到什么程度 |
|------|-----------------|
| RL | **物理意义层** — 量化债务表直接告诉你"哪些连续区域 RL 策略可以在里面自由探索而不会改变离散行为" |
| 感知 | **接口层** — 你的特征精度决定了同态度量——提供更细粒度的 feature，直接提升同态百分比 |
| 控制 | **安全边界层** — 量化债务 = 安全盲区。信任 [0.30,0.55) 内，无论怎么变化都不影响行为——这是隐藏的决策死区 |

## 核心公式 4：Schmitt 触发器（非对称阈值）

### 公式

```
Gate trigger condition:
  if signal > upper_threshold:  gate = ACTIVE
  if signal < lower_threshold:  gate = INACTIVE
  if lower ≤ signal ≤ upper:    gate = PREVIOUS_STATE  ← 迟滞
```

**面试一句话**："每个门有两个阈值——触发和复位不一样。这防止了信号在阈值附近振荡时门疯狂开关。这是 V6 选择 HardTanh 替代 Sigmoid 的工程原因——HardTanh 有真正的死区，Sigmoid 没有。"

**完整推导见**：[V5-V6 backplane 二、激活函数选型 — HardTanh vs Sigmoid 论证](../docs/V5-V6-mathematical-backplane.md) + [CLAUDE.md 不变式 #47](../CLAUDE.md)

**为什么不是 Sigmoid**：Sigmoid 的渐近残差（~0.01）泄漏噪声进入控制回路 → 极限环振荡 → 积分器饱和。HardTanh 的死区是真正的 0。

## 核心公式 5：Hoyer 稀疏度（结构判别）

### 公式

```
Hoyer(signal_vector) = (√n - ‖x‖₁/‖x‖₂) / (√n - 1)

n = 维度数（16）
‖x‖₁ = 各维度的绝对值之和
‖x‖₂ = 欧几里得范数
```

**面试一句话**："Hoyer 稀疏度区分'真的是多维度同时变化'和'一个传感器故障污染了多个维度'——只用一个标量，不需要单独训练异常检测模型。"

**完整推导见**：[mpc_kernel/safety_arbiter.py](../mpc_kernel/safety_arbiter.py) 的 `_compute_hoyer()` 函数

**工程直觉**：

| Hoyer 值 | 含义 | 仲裁器反应 |
|---------|------|-----------|
| → 1.0 | 只有一个维度在变化（可能是单传感器故障） | 降级到 Level 2（忽略该维） |
| → 0.0 | 所有维度均匀变化（真实的多维度事件） | 正常响应 |
| ~0.5 | 正常操作范围 | — |

## 三个面试常见的数学追问

### Q："Lipschitz ≤ 0.30 这个数字怎么来的？"

> "来自 PLAN2 盲测校准——2026 年 5 月 29 日对真人被试的测试。被试不知道 PLAN2 的存在，但确认系统'听得进去'。0.30 是当时信任 EMA 在两个标准差内的最大跳变。它可以调——但需要新的校准数据。它是经验校准的起点，不是神圣常数。"

### Q："拓扑同态 ≥ 50% 这说明什么？"

> "说明'相邻的连续状态产生相似行为'这个性质目前只在 50% 的情况下成立。另外 50% 的情况——连续状态变了，但离散行为没变，或者相反——这就是量化债务。我们的目标是 ≥ 65%。目前学术界没有人提出过这个度量——这是一个新的贡献。"

### Q："ODE 积分器和标准卡尔曼滤波器有什么区别？"

> "卡尔曼滤波器假设高斯噪声和线性动力学。我的 ODE 积分器不假设线性——它是脉冲响应 + EMA 弛豫，非线性，但仍然在 Lipschitz 约束的保证下不会爆炸。你可以把它看作一个'物理知情'的非线性状态估计器，针对的不是传感器噪声的协方差，而是状态本身的语义稳定性。"

## 不做的事（数学边界）

- 不训练感知模型（消费它们的输出，通过 Observer 接口）
- 不做端到端学习（系统结构是显式的——ODE、门路由、仲裁器——不是黑盒）
- 不追求数学的"最优性证明"（在开普勒时代追求托勒密式的本轮精度——方向错了）
