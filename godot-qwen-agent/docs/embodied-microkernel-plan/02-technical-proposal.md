## 一、行业痛点

当前具身智能领域面临一个结构性断层：

```
多模态大模型 (VLA)            ROS2 / ros2_control
─────────────────────         ─────────────────────
"大脑" — 战略规划                  "脊髓" — 执行
10-30Hz 低频决策                 1000Hz 高频控制
100-300ms 推理延迟               < 1ms 实时要求
缺乏物理常识                     缺乏变通能力
输出："把咖啡端过来"             输出：关节电流值
─────────────────────         ─────────────────────
                    ╲          ╱
              中间层缺失 — 谁来保证：
              ① 物理安全约束（不撞墙、不摔倒）
              ② 实时纠错（大模型幻觉 → 物理动作修正）
              ③ 连续状态 → 离散动作的数学映射
```

**现有方案的问题**：
- 纯 RL：黑盒，实机部署探索动作可能损坏电机
- 纯 MPC：计算量大，难以应对未知地形
- 规则引擎：泛化差，新场景需要新规则

## 二、我的方案：MPC+RL 融合微内核

### 核心定位

> **大模型与硬件之间的"小脑+脑干"层**  
> 定位为 `ros2_control` 框架的 Custom Controller 插件，
> 在进程内与 Hardware Interface 共享内存，绕过 DDS 延迟。

### 架构概览

```
多模态大模型（VLA）
  │ 输出：目标位姿 / 语义动作 / 粗略轨迹
  ▼
🌐 Observer 层：传感器 → StateVector（16维浮点向量）
  │
  ▼
🔧 MPC 内核（纯函数，零自然语言 I/O）
  ├─ ODE 积分器：连续状态演化（脉冲 + EMA，帧率无关）
  ├─ 8 门路由：优先级链（P0 紧急停止 → P7 社交规范）
  ├─ RL 策略槽位 ×3：Boundary / Cost / Value
  ├─ 安全仲裁器：Hoyer 稀疏度 + Lipschitz 约束（≤0.30）
  └─ ControlFrame 输出：安全动作 + 数据策略 + 审计追踪
  │
  ▼
ROS2 Hardware Interface → 电机驱动
```

### 关键数字

| 指标 | 数值 |
|------|------|
| 内核文件数 | 9 个（~2500 行纯 Python） |
| 决策延迟（纯内核） | ~1.7ms |
| 决策延迟（含感知） | < 5ms（目标） |
| 对比人类反应 | 快 40 倍（200ms → 5ms） |
| 代码依赖 | Python 标准库 + numpy（无 PyTorch, 无 ROS） |
| 测试覆盖 | 673 个测试，100% 通过 |
| 架构不变式 | 63 条（机器可执行） |

## 三、5 分钟 Demo：社交导航场景

> 场景：机器人在走廊遇到迎面走来的行人

```
t=0ms   摄像头捕获行人
        Observer 提取特征：social_intention = 0.4（正常行走）
        填充 StateVector 的 INSTANT 维度

t=5ms   ODE 积分器开始演化：
        social_intention 从 0.4 → 0.6
        （行人目光回避 + 身体微偏 → 隐性避让意图）

t=10ms  Route Controller：
        P1 门（SOCIAL_INTRUSION）接近触发阈值 0.58
        8 门链扫描：P0(无紧急) → P1(接近) → 锁定 P1

t=15ms  安全仲裁器确认：
        Lipschitz ‖Δs‖ = 0.12 ≤ 0.30 ✅
        Hoyer 稀疏度 = 0.3（各维度均匀变化，真实多维度事件，非单传感器故障）

t=20ms  ControlFrame 输出：
        action = YIELD
        params = { velocity: 0.3m/s, lateral_offset: 15° }
        safety_flag = GREEN

t=25ms  行人通过，social_intention 降回 0.3
        内核进入下一帧决策循环
```

**全程 < 5ms**（含 Observer 感知推理约 3ms + 内核 ~1.7ms）。

## 四、数学骨架（面试必备的 3 个核心公式）

> 完整推导见 [../docs/V5-V6-mathematical-backplane.md](../docs/V5-V6-mathematical-backplane.md)（1791 行）。

### 公式 1：帧率无关 ODE 演化

```
ds/dt = -α·(s - s_target) + β·δ(t - t_event)

离散化：s_{t+1} = s_t + (1 - exp(-dt/τ)) · (s_target - s_t) + β·I_event
         ↑                    ↑                                  ↑
    上一帧状态          EMA 弛豫（帧率无关）             脉冲响应（事件触发）
```

**面试时只讲这一句**："我的内核用 `1-exp(-dt/τ)` 做状态演化——无论调用间隔是 1ms 还是 1s，动力学行为不变。所以同一套内核能同时驱动对话 Agent 和机器人。"

### 公式 2：安全仲裁器的 Lipschitz 约束

```
‖StateVector_{t} - StateVector_{t-1}‖₂ ≤ 0.30

如果超出 → Safety Arbiter 降级：
  Level 1: 沿用上一帧 ControlFrame（输出平滑）
  Level 2: 切换到纯 PD 阻抗控制（忽略 RL 策略）
  Level 3: 紧急停止（P0 门强制触发）
```

**面试时只讲这一句**："内核保证连续两帧之间状态变化不超过 30%。如果某帧突然跳变（比如传感器故障），仲裁器自动降级——不需要单独训练异常检测模型。"

### 公式 3：连续 → 离散映射的拓扑同态

```
连续控制面 (drift, clarity, trust, e(t))  →  离散行为空间 (GENERATE / YIELD / STOP / ...)

当前同态度量 ≥ 50%（4 个连续变量，19 个可观测离散行为状态）
目标：≥ 65%（V8.0 路线图 — 通过 Planning LLM 契约注入）
```

**面试时只讲这一句**："从连续数学到离散动作的映射，我用拓扑同态度量来保证'相邻的连续状态产生相似的离散行为'——当前基准 50%，学术界尚无同类度量。"

## 五、与青云课题组六项工作的对应

| 课题组工作 | 我的内核已有支撑 | 进组后论文方向 |
|-----------|----------------|--------------|
| **工作1** 社会规则认知导航 | Route Controller 的 P1（社交距离入侵）和 P7（社交规范违反）门可替换为社交导航专用门函数 | 方向① MPC微内核 + 方向⑤ 帧率无关ODE |
| **工作2** 多源传感器融合→隐性意图 | Observer 架构 + CPU Adapter 将多模态特征翻译为统一 StateVector。多模态融合本身是他们的强项，我提供"融合后怎么做安全决策" | 方向③ Hoyer+Lipschitz |
| **工作3** 人体位姿估计 | 通过 Observer 接口消费位姿估计输出（非我强项，期待与做感知的协作者互补） | — |
| **工作4** 人机协同决策 | **绝对主场**。契约驱动降级（contract_violation）+ 连续状态空间博弈 + 策略可插拔（RL 槽位），代码直接覆盖工作4 的所有关键词 | 方向①④⑥⑦ |
| **工作5** 数字孪生/持久记忆 | V7.4 恒等流形 M_id ⊂ ℝ¹² + OU 过程均值回复，就是数字孪生的数学形式——课题组说的"用户画像在线学习"，我的代码已经做了 | 方向④⑦ |
| **工作6** 跨场景自适应 | 量化债务表（度量连续→离散映射质量）+ 帧率无关 ODE（动力学不依赖时间步长）+ 拓扑同态 ≥50% | 方向②⑤ |

> 关键信息：**工作 3 我诚实标注"非我强项"**。课题组大概率有其他人专门做位姿估计。我消费他们的输出——这是互补，不是短板。
