## 一、五大核心原则

### 原则 1：现状与想法严格分离

> "你不能给出你没有的东西。"

| 场景 | ✅ 正确话术 | ❌ 错误话术 |
|------|-----------|-----------|
| 描述性能 | "目前在仿真中稳定跑 1000Hz。但引入真实传感器噪声后，MPC 求解器出现长尾延迟——这是我进组后首要解决的。" | "我的内核完美解决了延迟问题，能稳定跑 1000Hz。" |
| 描述缺陷 | "我必须坦诚，离散化截断误差在剧烈运动下会导致系统能量计算失真。这是我的 Open Question #2。" | "系统很稳定，没什么大问题。" |

### 原则 2：弱化功利性，带着问题来

> "我是带着具体的 Bug 和未解之谜来的，希望能在这里和大家一起把这块硬骨头啃下来。"

**面试结尾标准话术**：
> "我今天带着这个只有 9 个文件的微内核来，并不是为了证明我已经做出了一个完美的系统，而是为了证明我具备从零推导底层数学逻辑、并将其工程化的能力。我知道这个内核目前还有很多缺陷，我之所以非常渴望加入咱们课题组，是因为我遇到了仅靠我个人算力和设备无法跨越的物理边界，而咱们这里有国内最好的硬件平台和理论指导。我是带着具体的 Bug 和未解之谜来的。"

### 原则 3：AI 是打字员，我是架构师

**场景**：面试官问"你是用 AI 写的吗？"

> "AI 是我的打字员，帮我处理了样板代码和 API 调用。但核心的——状态空间方程、MPC 的 Hessian 矩阵推导、离散化步长的选择、Schmitt 触发器的死区宽度——是我在纸上推导出来的。我可以现在在白板上推导核心的代价函数。"

**场景**：面试官追问"如果现在让你脱离 AI，你能手写出来吗？"

> "纯函数内核的 9 步决策链（Step 0-8）我可以手写——因为每一步的数学定义都在我的文档里。Rust 重写内核已经在 V10 路线图中。但如果你问的是全套测试和总线层——那些样板代码我会用 AI 辅助，因为它们是工程体力活，不是核心智力贡献。"

**场景**：如果对方明确反 AI 辅助编码  
> "是的，我理解这个顾虑。如果所有 AI 辅助的代码都不可信，那编译器和 linter 也不可信——它们也是机器生成的。我的态度是：**.ai_reasoning/ 里保存了每个决策的推导过程——你可以看到哪些是我在纸上算的（数学推导）、哪些是 AI 帮我格式化的（样板代码）。** 核心的状态空间方程、Hessian 矩阵推导、Lipschitz 常数的选择——这些是数学，不是 AI。数学不怕审查。"

### 原则 4：数据采集的卡点在决策层

> "数据本身不值钱，带有物理因果标签和安全边界验证的高质量交互数据才值钱。这个标签只能由底层决策内核来打。"

**面试场景**：面试官说"我们最大的问题是缺数据"  
**你的回应**：
> "我注意到行业里都在谈数据缺口，但我认为真正的瓶颈不在传感器端，而在决策层对'什么是好数据'的定义能力上。现在的采集大多是开环的、被动的，导致 1000 小时数据里 99% 是机器人在原地发呆。我的 MPC 内核本质上是一个'高质量数据生成器'——通过 MPC 保证探索过程始终在物理安全边界内，通过 RL 最大化每次交互的信息增益。只有当决策层具备了物理理解能力，数据采集才能从体力活变成智力活。"

### 原则 5：超纲问题四步应对

> 坦诚边界 → 降维拆解 → 反向请教 → 情绪价值

**示例**：面试官问"如果你的 RL 策略在 Sim2Real 时发生了严重的 Reward Hacking，你的微内核怎么兜底？"

1. **坦诚边界**："这个问题非常犀利，直接切中了 Sim2Real 最痛的点。老实说，我目前的微内核在应对极端的 Reward Hacking 时，兜底机制确实还不够完善。"

2. **降维拆解**："我目前的防线主要依赖 MPC 的物理硬约束——关节力矩上限、速度极限和碰撞预检——来防止硬件损坏。但对于'动作逻辑上的荒谬'——比如机器狗为了拿高分在地上疯狂打滚——我的内核目前确实缺乏有效的语义级拦截。"

3. **反向请教**："如果是您团队在处理这类 Sim2Real 的 Reward Hacking 时，通常会在控制层做哪些先验知识的注入？"

4. **情绪价值**："您刚才提问的角度非常有启发，让我意识到单纯靠物理约束是不够的。"

## 二、高频问题速答

### Q1："你一个人做的？"

> 指 [00-project-evolution.md](./00-project-evolution.md)。"是的。但'一个人'不意味着'一次性'。项目从 RAG 问答 bot 起家，经历了 4 次架构跃迁。100 个决策文件，每个都记录了 alternatives 对比。演化过程的密度就是最好的防伪——你可以看我的 git log 验证每一个时间点。"

### Q2："做完之后呢？"

> 指 00 的结语。"这个项目不是因为'做完了'而停止的。它有 7 个可从现有代码和数学推导中直接展开的论文方向。我是带着一个有 7 个论文分支的活系统来求合作的。"

### Q3："你还有什么想法？"

> 从 7 个论文方向选 1 个展开。"最让我兴奋的是方向 ④——契约驱动降级。现有安全 AI 工作只关注物理安全，但机器人进入人类社会后，需要的是'社会契约安全'——什么时候应该主动退让、什么时候应该请求人类介入。我的代码里已经有了 contract_violation 的完整审计链路，下一步只需要在真实社交场景中做人类被试实验。"

### Q4："你用过 ROS2 吗？"

> "我没实际部署过 ROS2 节点。但我的 Event Bus Protocol 设计时就是以 ROS2 topic 为假想目标的——事件类型直接映射到 topic、优先级仲裁映射到 QoS、Lamport 时钟映射到 ROS 的时间戳。如果你让我部署，我需要的是 ROS2 的 API 文档，而不是重新设计架构。"

### Q5："你有顶会论文吗？"

> "没有。但我的 `.ai_reasoning/` 目录里有 71 个工程决策文件，每个都记录了 alternatives 对比和 anti-patterns。我写代码的方式就是写论文的方式——提出假设、列出替代方案、做消融实验、记录结论。只是还没投稿。如果可以，我希望第一篇论文能在您的指导下完成。"

### Q6："你的内核和 NVIDIA Isaac Sim / ROS2 的 controller 有什么区别？"

> "Isaac Sim 是仿真环境，ROS2 controller 是执行层。我的内核位于两者之间——它消费仿真/真实传感器的输出，做出决策后下发到 controller 执行。更准确的类比是：如果 ROS2 controller 是 Linux 内核的驱动层，我的内核就是 Linux 的调度器——它决定'现在该做什么'，而不是'怎么做'。"

## 三、面试结尾反问（选 1-2 个）

1. **"贵组做决策层时，是用规则引擎还是 RL？遇到过状态空间连续性的问题吗？"**  
   → 展示你已经在思考对方的问题域

2. **"您觉得具身智能领域，目前最被低估的技术瓶颈是什么？"**  
   → 开放问题，对方会透露课题组的真实痛点

3. **"如果我把这个微内核开源，您认为学术界会怎么批判它？"**  
   → 展示学术心态，同时获取外部视角

4. **"您的课题组里，做感知和做控制的人之间，目前是怎么协作的？"**  
   → 了解对方的工作流，判断内核能否嵌入

5. **"这 7 个论文方向里，您觉得哪个对课题组最有价值？"**  
   → 用论文方向反套对方兴趣，了解组里优先级

## 五、面试前 30 分钟检查清单

- [ ] 能 30 秒说出"我的项目做什么"（大脑-小脑-脊髓比喻）

- [ ] 能写出 3 个核心公式的"一句话解释"
- [ ] 能说出 7 个论文方向的名称和对应会议
- [ ] 能说出当前最大的 3 个缺陷（长尾延迟、离散化误差、语义映射黑盒）
- [ ] 能说出最想进组解决的 1 个问题
