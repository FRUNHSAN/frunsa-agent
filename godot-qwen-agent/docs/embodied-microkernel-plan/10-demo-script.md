# 10 — 5 分钟 Demo 精确脚本

**定位**：面试或组会报告时的精确时间线脚本。排练 3 遍形成肌肉记忆。  
**目标**：5 分钟内让听众理解三件事——你的内核做什么、数学骨架是什么、为什么你需要他们的实验室。

---

## 完整脚本（按秒计时）

### 0:00-0:30 — 一句话开场

> "我做的是一个**具身智能的决策层微内核**。它位于大模型和硬件之间——大模型负责'战略'（把咖啡端过来），硬件负责'执行'（电机转动），我的内核负责'战术'——在大模型的低频指令和硬件的高频控制之间，做实时物理安全兜底。  
> 内核只有 9 个文件，~2500 行纯 Python。不依赖 PyTorch，不依赖 ROS。纯函数——输入 16 维浮点向量，输出安全动作。"

### 0:30-1:30 — 架构白板手绘

在白板上画出：

```
大模型（~10Hz） → [你的微内核] → ROS2（~1000Hz）
战略层               战术层            执行层

微内核内部：
  ODE 积分器（连续状态演化）
  → 8 门路由（优先级决策）
  → 安全仲裁器（物理约束）
  → ControlFrame（安全动作输出）
```

口述："从传感器读数到安全动作输出，全程 < 5ms。比人类反应快 40 倍。同一套内核能驱动对话 Agent 和机器人——因为它输入输出都是浮点数，不关心这些浮点数来自对话文本还是激光雷达。"

### 1:30-2:30 — 仿真 Demo 演示

展示社交导航场景（或任何已准备好的仿真）：

> "这是一个具体的场景：机器人在走廊遇到迎面走来的行人。  
> 看这里——当 social_intention 从 0.4 漂移到 0.6（行人目光回避），P1 门在 10ms 内触发，输出 YIELD 动作：减速到 0.3m/s，偏右 15°。  
> 注意：全程没有大模型参与——这是纯粹的 ODE + 门路由 + 仲裁器的本地决策。大模型告诉它'跟着这位老人走'，但'怎么跟、多近、何时让路'——是内核在本地做的。"

### 2:30-3:30 — 数学骨架

在白板上写出 1 个公式：

```
ds/dt = -α·(s - s_target) + β·δ(t - t_event)

离散化：s_{t+1} = s_t + (1-exp(-dt/τ))·(s_target - s_t) + β·I_event
```

口述："这个公式只有三个参数——α（弛豫速率）、β（脉冲强度）、τ（时间常数）。但它保证了：  
1. 帧率无关——调用间隔是 1ms 还是 1s，动力学行为不变  
2. 连续演化——没有 'if state > threshold' 的分支  
3. 零自然语言——整个内核没有一句 prompt，全是 float"

然后展示时序预算表：

| 步骤 | 时间 |
|------|------|
| ODE 积分 | ~0.5ms |
| 8门路由 | ~0.1ms |
| 安全仲裁 | ~0.3ms |
| **总计** | **~1.7ms** |

### 3:30-4:30 — 已知缺陷 + 希望在贵组解决的问题

> "现在我要诚实地告诉各位这个内核的三个已知缺陷：  
> 
> 1. **Sim2Real 长尾延迟**——仿真里稳定 1000Hz，但真实传感器的噪声下 MPC 求解器会出现长尾延迟。我需要真实机器人来标定这个边界。  
> 
> 2. **离散化截断误差**——剧烈运动时，固定步长导致能量计算失真。我需要和做非线性控制的老师探讨自适应变步长。  
> 
> 3. **语义→权重映射黑盒**——我想用大模型指导 MPC 的权重选择，但缺乏真实场景数据。  
> 
> **这三个缺陷就是我为什么想进贵组。** 我带着具体的 Bug 来的——不是来镀金的，是来做思想碰撞的。"

### 4:30-5:00 — 收尾 + 反问

> "最后，这个项目不是因为'做完了'而停止的。它有 7 个可从现有代码和数学推导中直接展开的论文方向。我是带着一个有 7 个论文分支的活系统来求合作的。  
> 
> 我想请教一个问题——**您觉得具身智能领域，目前最被低估的技术瓶颈是什么？**"

---

## 排练要点

### 必练 3 遍的段落

1. **开场 30 秒**（0:00-0:30）— 必须练到不看稿、自然流出
2. **数学公式解释**（2:30-3:30）— 练到边写边讲，不停顿
3. **缺陷告白**（3:30-4:30）— 练到语气诚恳、不卑不亢

### 时间控制

| 如果超时 | 砍掉什么 |
|---------|---------|
| 如果剩 3 分钟 | 砍 Demo（1:30-2:30），只讲架构 + 数学 + 缺陷 |
| 如果剩 2 分钟 | 只讲架构 + 缺陷告白 |
| 如果剩 1 分钟 | 只讲开场 30 秒 + 缺陷告白 |

### 防翻车准备

- 如果 Demo 跑不起来 → "这正是我说的 Sim2Real 问题——仿真环境下的不确定性。我们直接看架构图吧。"
- 如果白板公式写错了 → "让我重新写——这个公式我推导过，只是需要确认符号。"
- 如果被问到完全陌生的领域 → 用四步应对公式（坦诚边界 → 降维拆解 → 反向请教 → 情绪价值）
