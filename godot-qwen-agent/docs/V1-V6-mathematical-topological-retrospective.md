# V1 → V6：从契约内核到控制面 — 数学与拓扑学回顾

**日期:** 2026-06-09
**状态:** V6 封板后的结构性复盘
**目标:** 回答"每个版本在数学上做了什么？拓扑结构发生了什么变化？"

---

## 零、整体视角：一个智能体的两个自适应关系

```
Agent ↔ Human:    自适应契约 (V1 → V5) — "关系如何演化"
Agent ↔ Task:     引擎控制面 (V5 → V6) — "执行如何自适应"
Agent ↔ Environment: 循环拓扑 (V7 →)  — "物理如何反馈"
```

项目从 Day 1 就在做自适应——但不是"自适应参数"，而是**自适应结构**。每个版本都在数学上向更抽象、更形式化的方向推进一步。

---

## V1-V2：契约的离散拓扑（离散集合上的关系）

**数学结构：有限自动机**

```
状态:    Blueprint = {verbosity, tone, initiative, ...} (有限集)
转移:    δ: Blueprint × Event → Blueprint
事件:    fatigue_detected, trust_threshold_reached, renegotiation_requested
```

**拓扑视角：离散拓扑。** 每个 Blueprint 字段是一个孤立的点——它们之间没有连续性，没有距离，没有梯度。自适应 = 在有限集合上做状态跳变。

**核心贡献：契约原语的建立。** 定义了"自适应契约"的基本概念——它不是参数优化，是关系状态的转移。为后续所有版本提供了语义基座。

**局限：** 离散转移只能表达"从 A 到 B"，不能表达"向 A 靠近了多少"。没有梯度就没有方向感。

---

## V3：契约的纤维化（参数空间上的丛）

**数学结构：纤维丛 (Fiber Bundle)**

```
底空间 B:    用户身份 (uid) — 离散
纤维 F:      Blueprint 实例 — 连续参数上的一个点
全空间 E:    所有用户的所有可能契约状态
投影 π:      E → B，把每个契约投影到它的所有者
```

**拓扑视角：平凡丛。** 每个用户是一个孤立的纤维——用户的契约在自己纤维上演化，其他用户的演化不影响它。没有跨纤维的平行传输。

**核心贡献：多用户隔离。** 契约不再是一个全局单例——每个用户有自己独立演化的契约纤维。为后续版本的"信任是 per-user 累积量"奠定了基础。

**局限：纤维间无通信。** 没有"学习其他用户的行为模式"——没有范畴，只有集合。

---

## V4：导子的引入（参数空间上的切空间）

**数学结构：微分流形 S ⊂ ℝ^n**

```
状态:    x ∈ S (信任值、疲劳水平、能量状态...) — 不再是离散的有限集
流:      dx/dt = f(x, u)  — 连续的动力学
控制:    u = π(x)          — 策略函数
```

**拓扑视角：光滑流形。** V1-V3 的离散拓扑被连续流形替代。状态之间有了距离概念——"信任 0.10" 和 "信任 0.15" 是两个不同的位置，可以计算梯度。这是从"开关"到"推子"的跃迁。

**信住 EMA、贝叶斯方差、能量状态机。** 这些都是在连续流形上定义动力学——信住以不对称速率衰减，方差以 gamma 因子收缩，能量状态需要 2 轮确认。

**核心贡献：连续动力学的引入。** 自适应从 if-else 跳变变成了 dr/dt = f(r, ...)。为 V5 的 Wasserstein 流奠定了流形基座。

**局限：流形上只有动力学，没有控制论。** dr/dt 描述了"状态怎么变"，但没有解答"我应该怎么干预"。这需要 V5 的反馈控制。

---

## V5：控制面的诞生（从动力学到反馈控制）

**数学结构：观测-控制回路 (Observer-Controller Loop)**

```
观测:    y = h(x)           (WassersteinProxy, TrackingError)
控制:    u = K(y)           (MetaAdaptTrigger, Lambda 调度)
执行:    a ~ π(·|x)         (LLM 文本生成)
选择:    x ← 用户反馈        (选择压力)
```

**拓扑视角：纤维丛上的联络 (Connection on a Fiber Bundle)。**

V3 的纤维丛是平坦的——没有纤维间通信。V5 引入了**联络**：一个告诉我们"如何从纤维上的一个点移动到另一个点"的结构。联络的曲率度量了平行传输的路径依赖性——在 V5 中，曲率等价于"用户类型特异性"：两个不同的用户，从同一个起点出发，可能平行走到完全不同的终点。

**四条控制面 = 四个联络分量：**

| 控制面 | 观测信号 | 控制动作 | 联络方向 |
|--------|---------|---------|---------|
| Path 1 | e(t) — 跟踪误差 | relax / escalate 选择阈值 | 纵向 (能力方向) |
| Path 2 | σ² — 意图方差 | Planning n + Critic θ | 横向 (搜索方向) |
| Path 3 | 截断率 | 管道倍率 | 输出方向 |
| 路由 | e(t) trend | A / C 二元切换 | 结构方向 |

**核心贡献：反馈控制的数学形式化。** 自适应不再是"参数自更新"——它是观测-控制-执行-选择的完整回路。Pontryagin 最优控制（Bang-Bang 路由）、Lagrangian 松弛（λ 增益调度）、Lyapunov 稳定器（θ floor）全部就位。

**局限：控制面在语义层运行，控制信号没有触及引擎——它们在引擎外围调节参数。引擎内部（Planning 怎么拆解？Orch 怎么调度？Critic 怎么打分？）仍然是 LLM 概率采样的黑盒。**

---

## V5.1-V5.3：从单信号到信号分解

**V5.1 — Lambda 增益调度：** Planning 首次引入外部信号（λ = f(trust, e_t)），但用的是连续统的单一标量。为拉格朗日乘子进入引擎层开了门。

**V5.2 — Observer Downgrade：** 观测器从"控制器"降级为"传感器"。Principle #5（Observe, Don't Inject）。这是**信号与执行器解耦**的首次显式化——未标定的传感器不配做前馈。

**V5.3 — 双传感器融合：** 从 σ² 单信号裂变为 drift ⊕ clarity。这是 V5 内部第一次"信号分解"——两个传感器测量两个正交维度（轨迹 vs 状态），用数学融合（清醒压制 + OR 逻辑）替代关键词列表。

**拓扑视角：切空间的维数扩展。** V5.1 的切空间 TmS 只有 σ² 一个方向。V5.3 的切空间有两个基向量——drift 和 clarity。下一步 V6 再把 e(t) 加进去。

---

## V6：引擎层的相变（控制面穿透引擎）

**数学结构：信息导向的随机最优控制**

```
Planning:   n = branch_count(Φ(d, c))              — rate-distortion optimization
Orch:       depth = Kahn_BFS(Sᵢⱼ tag matching)     — partial-order scheduling
Critic:     θ = f_drift(d) × g(e_t) × gain        — hypothesis testing with ROC sliding
```

**拓扑视角：从流形到图。**

V5 的控制面运行在**连续流形**上——σ², e(t), drift, clarity 都是实数。V6 把控制面穿透到了**离散图结构**上——DAG 的节点和边。

这是两个范畴之间的**函子 (Functor)**：

```
F: 连续控制范畴  →  离散执行范畴
   σ², e(t)    ↦   branch_count ∈ {1, 2, 3}
   f_fused     ↦   parallel_depth ∈ {1, 2, 3}
   drift, clarity ↦ θ ∈ [0.50, 0.75]
```

**函子 F 保持了结构，但改变了分辨率。** 连续流形上的小扰动（drift 从 0.49 到 0.51）映射到离散拓扑上的跳变（BALANCED → EXPLORE）。这是一个**保结构降阶**——V5 数学基座的核心承诺。

#### V6.1 — DAG 拓扑相变

```
V6 前: asyncio.gather — 假设 D = 0 矩阵 (所有任务独立)
V6.1: tag 匹配 → Kahn 环检测 → BFS 层级 → Semaphore(parallel_depth)
```

**拓扑意义：** 从 0 维（单点全并行）到 1 维（DAG 的 1-骨架）。Kahn 算法的拓扑排序是图论中最基础的不变量——它告诉我们"哪些顶点可以在不破坏偏序的情况下同时处理"。

#### V6.2 — Wasserstein 混合校准

```
σ²_smoothed = (α·σ²_base + n·σ²_session) / (α + n)
gain ∈ [0.5, 2.0], always subordinate to f×g
```

**拓扑意义：** 嵌入空间的度量校准。Wasserstein 距离是概率分布空间上的度量——它是切空间 TmS 上最自然的黎曼度量。校准让它从"原始 cosine distance"变成"归一化的 L=1 Lipschitz 映射"。

#### V6.3 — 偏置张量裂变

```
relax_bias → explore_bias ⟂ compromise_bias
两个正交方向分别驱动 Planning（搜索）和 Critic（宽容）
```

**拓扑意义：** 切空间的基向量分解。V5.3 把观测（drift ⟂ clarity）分解了，V6.3 把控制（explore ⟂ compromise）也分解了。切空间 TmS 现在有四个基向量：drift, clarity, explore_bias, compromise_bias。

## V1→V6 的拓扑演化总览

| 版本 | 数学结构 | 拓扑对象 | 核心不变性 |
|------|---------|---------|----------|
| V1-V2 | 有限自动机 | 离散拓扑 | 契约原语 |
| V3 | 纤维丛 | 平凡丛 (无联络) | 多用户隔离 |
| V4 | 光滑流形 | 切空间 TmS | 连续动力学 |
| V5 | 观测-控制回路 | 丛上的联络 | Pontryagin + Lyapunov |
| V5.3 | 双传感器 | 切空间的 2-维基 | drift ⟂ clarity |
| V6 | 函子 F: 连续 → 离散 | DAG 的 1-骨架 | 保结构降阶 |
| V6.3 | 张量裂变 | 切空间的 4-维基 | explore ⟂ compromise |

**演化方向 = 从 0 维到 n 维的维数推进 + 从离散到连续再到离散-连续混合。**

```
V1-V3: 0 维 (点) → V4: n 维流形 → V5: 流形上的动力学 → V6: 流形 + 图 → V7: 流形 + 图 + 循环
```

---

## V6 的拓扑残余（V7 要消化的）

V6 做到了"控制面穿透引擎层"——连续信号驱动离散执行。但有三个拓扑残余：

**残余 1：循环的隐式化。** retry 逻辑嵌在 Track C 的 while 循环里——它不是一种形式化的拓扑结构，是一个 while True 块。循环作为 1-态射的反馈边，没有被显式建模。

**残余 2：语义层和物理层的分离。** V6 的 DAG 只处理语义步骤间的依赖。物理操作（"跑这段代码"）和语义操作（"解释这段代码"）在 DAG 上没有拓扑差异——它们是一样重的节点。没有阻力场，没有物理预算。

**残余 3：Agent ↔ Environment 的自适应缺失。** V5 形式化了 Agent ↔ Human 的自适应，但 Agent ↔ Environment 的关系——编译成功/失败如何影响系统状态、如何影响后续决策——没有被建模为一种"关系"。它是单次事件的记录，不是累积的契约。

**V7 的任务：把这三个残余全部消化。** 循环拓扑化消化残余 1。物理 Critic + 阻力场消化残余 2。环境事件作为选择压力源消化残余 3。

---

## 结语：从代数到几何再到拓扑

V1 用的是**代数**（离散规则、if-else 分支）。V4-V5 引入了**几何**（流形、切空间、梯度、联络）。V6 开始引入**拓扑**（DAG、图论不变量、BFS 层级）。V7 的循环拓扑化是拓扑的深化——从 1-范畴到 2-范畴。

这不是"三个不同的框架"——这是**同一个实体在三个数学视角下的投影**。代数视角告诉系统"什么是对的"，几何视角告诉系统"离目标有多远"，拓扑视角告诉系统"不同部分之间如何连接"。

一个完整的控制论智能体，三者缺一不可。
