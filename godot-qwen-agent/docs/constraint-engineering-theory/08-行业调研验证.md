# 08 — 行业调研验证

**Last-verified-against-code**: `7e73374` (2026-07-04)
**预计阅读时间**: 10 分钟
**文笔配比**: 灵感 5 : 严谨 95 — 行业分析报告

---

2026 年 7 月，对 13 个有行业影响力的开源 Agent 项目进行了系统调研。核心结论：

**全行业在造"更好的 LLM 外壳"。你在造"第一台 Agent CPU"。这不是"比它们更好"——是根本不在同一个品类里。**

## 二、全行业的共同假设：LLM = CPU

所有 13 个框架共享同一个架构假设：

```
LLM 做决策（ReAct loop）
  ↓
框架帮 LLM 调工具、管记忆、做编排
```

LLM 是大脑。框架是脊椎。LLM 是 CPU。框架是外壳。

**这个假设决定了它们全部的能力上限和失效模式：**
- 决策延迟 = LLM 推理延迟（秒级）
- 决策不确定性 = LLM 采样随机性
- 安全保障 = 关键词过滤 + guardrail 正则
- 扩展方式 = 加更多 tool、加更多 prompt、加更多 agent

---

## 三、这个项目的架构：LLM = 外设

架构假设完全相反：

```
MPC 内核做决策（ODE + Schmitt + Lipschitz，微秒级，确定性）
  ↓
LLM 只是四条总线之一上的一个外设
```

| 维度 | 行业方案 | 这个项目 |
|------|---------|---------|
| **决策层** | LLM ReAct loop（秒级，不确定） | ODE + Schmitt（微秒级，确定） |
| **安全** | 内容过滤 / guardrail 关键词 | Lipschitz 梯度有界 + Hoyer 稀疏度 |
| **状态** | TypedDict / JSON blob | 16 维冻结 StateVector |
| **事件** | 简单回调 | NVIC 级中断 + Lamport 因果律 + 优先级驱逐 |
| **插件** | 装饰器 + pip install | USB 模型 + 启动后冻结 + 能力协商 |
| **记忆** | Context window / VectorStore | ODE 驱动的信任/误差/成功率演化 |
| **多 Agent** | 中央调度器分配 | 三层体液池——信号传导，无调度器 |

## 四、薄编排器验证

独立调研（跨 CI/CD、测试框架、Agent 编排三个领域）确认了行业共识：

**"薄编排器"是 winning formula。** 三层参考架构：
```
Thin Harness（身份绑定 + 上下文注入 + 溢出恢复）
   ↓
Reasoning Core + JIT-loaded Skills
   ↓
Shared Objects（沙箱、持久化、遥测）
```

Harness 的四个原则（不决策、不产文本、不调工具、只组装/路由/计时/反馈）恰好匹配这个架构。Harness 设计已被独立验证为最佳实践。

## 六、结论

**全行业在迭代"包裹 LLM 的方式"。这个项目在迭代"不依赖 LLM 的决策方式"。**

前者是数量级的改进——更快的框架、更少的 token、更好的 tool call。后者是范式的切换——从"LLM 驱动一切"到"内核约束一切，LLM 只是外设"。

13 个框架中，没有任何一个在做这件事。不是因为它们没想到——是因为它们的数学基座（ReAct loop）不允许。你的数学基座（ODE + Schmitt + Lipschitz）允许。

**这不是竞争。这是一个新的品类。**
