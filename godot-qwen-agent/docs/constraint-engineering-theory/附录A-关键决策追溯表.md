## 一、新增字段说明

每条决策新增两个必填字段：

| 字段 | 含义 | 示例 |
|------|------|------|
| **工程判据** | 这个决策是否正确，由哪个测试/指标说了算？必须可测量、可 falsify。 | `h(x) ≥ 0 在所有帧上保持` |
| **失效模式** | 如果判据失败，回溯到哪条公理的哪个前提是错的？必须追溯到公理或铁律。 | `公理 1 违反——h(x) 的形式推导在物理域不成立` |

**核心逻辑**：楼梯 demo 里的每一帧穿模不只是"bug"——它是**对该行决策的工程判据的反驳**，自动触发对相应公理的重新审查。

**判据失败 → 回溯路径**：

```
判据失败
  │
  ├── 追溯到本表"失效模式"列 → 定位被违反的公理/铁律
  │
  ├── 追溯到 .ai_reasoning/chains/ → 该公理的推导链是否有漏洞
  │
  └── 决策修正 or 公理修正 → 不是"修 bug"，是"修约束"
```

## 三、L1 层决策 —— 数学与架构基础

|---|----------|---------|---------|---------|---------|
| B1 | ODE `1-exp(-dt/τ)` = Michaelis-Menten 同构 | 第 4 轮 | 02 | τ 值在毫秒级（游戏引擎域）和秒级（Agent 域）使用相同公式，无需修改形式 | 游戏引擎域中 ODE 积分器产出周期性振荡（应弛豫到 target 但持续 overshoot）→ `1-exp(-dt/τ)` 的形式在毫秒级不满足帧率无关性。回溯到铁律 #2（连续控制律）——连续形式的离散化在 dt→0 极限外失效 |
| B2 | Lipschitz `‖Δsv‖ ≤ 0.30` = 膜电位上限 | 第 4 轮 | 02, 05 | 安全仲裁器的 `CRITICAL_CLAMP` 仅在传感器故障（单维跳变 >5×）时触发，不因正常物理运动触发 | `CRITICAL_CLAMP` 在正常游戏场景中高频触发 → 0.30 的全局常数在物理域过于激进。回溯到铁律 #6——常数需要从全局升级为域特定（前沿注入 [B3]） |

| B4 | (X, D, π, ψ) 四元组 | 第 5 轮 | 07 | kernel_step() 的纯度：相同 (X, D, signals) → 相同 (π 输出, ψ 模式) | 相同输入产生不同输出 → 铁律 #4（形式化可重放）被破坏。回溯到铁律 #1（纯函数边界）——内核内部有隐式状态泄漏 |

## 七、判决流程：从判据失败到公理修正

当任意工程判据失败时，按以下流程处置：

```
1. 定位本表中对应的"失效模式"列 → 确定被违反的公理/铁律
2. 检索 .ai_reasoning/index.yaml → 找到该公理的推导链
3. 读取推导链的 Rationale 节 → 检查形式推导和参数标定
4. 分三种结果:
   a) 推导链的形式正确，参数标定在物理域不适用 → 触发参数标定任务（前沿注入 [A1]）
   b) 推导链的形式在物理域有漏洞 → 触发约束修改（Protocol 4, ERROR 级别, 需人工确认）
   c) 推导链的形式在物理域完全不成立 → 触发公理修订（Protocol 4, L3 级别, 需人工确认 + 新推理链）
5. 产出新推理链 → 更新本表对应行的"工程判据"（因为约束已修改）
```
