# 09 — 边界与反驳

**Last-verified-against-code**: `7e73374` (2026-07-04)
**预计阅读时间**: 15 分钟
**文笔配比**: 灵感 40 : 严谨 60 — 学术 Peer Review 的 rebuttal。主动攻击自己的弱点

---

一份只讲"为什么我是对的"的哲学宣言，说服力远低于一份同时讲"我在哪里可能是错的、什么条件下这个框架会失效"的文档。**敢说"我可能是错的"的人，比只说"我一定是对的"的人更值得信任。**

以下是约束式工程论目前已知的六条结构性裂缝。每一条都不是"还没解决的问题"——是"约束范式本身的结构性边界"。

---

## 裂缝一：样本量不对等——40 亿年 vs 40 分钟

生物免疫系统有 40 亿年的试错数据。每一个死掉的生物个体都是一次"这个约束组合不对"的反馈。

你的系统能有多少数据？几百轮对话？几千次工具调用？

胸腺筛选在历史上用天文数字的死亡换来了免疫系统的基本可靠。你要在小几个数量级的样本上做同样的事。**白细胞必然会在正常场景下误触发。不是可能——是必然。**

样本量不是"当前不够"。它是约束范式的结构性边界：**约束式工程需要的选择压力数据量，和单用户 Agent 系统能产生的数据量之间，存在根本性的不对等。**

---

## 裂缝二：单信号源——谁在监控监控者

白细胞分化由 `|d(trust)/dt| > η` 触发。trust 是 ODE 积分器算出来的。ODE 积分器的参数标定不全——你们自己文档说了"全部默认值未经经验标定"。

**如果 trust 的计算本身有系统性偏差，免疫系统就在对错误信号做出反应。**

真实生物有冗余——痛觉、温度、压力、化学梯度都在并行提供独立于 trust 的信号。你的系统只有一个 trust 维度。单信号源的免疫触发 = 单点故障。

这不是"加更多维度"能解决的——这是自我指涉问题的工程形式。监控者自身就是被监控对象的一部分。当两者同时失效时，没有外部纠偏。

---

## 裂缝三：记忆 = 过拟合——B 细胞会过敏

B 细胞的 RL 策略从历史危机中学习。但危机模式会演化。

全新病原体出现（类比你系统中的新型信任塌缩模式）时，先天免疫（白细胞 + 三层缓冲）先顶上。适应性免疫（B/T 细胞 = RL 策略）需要时间才能产生有效应答。在这段时间里，**你只能靠非特异性防御**。这和 COVID-19 原始株的应对逻辑完全一样——在疫苗出来之前，靠的是社交距离和口罩（非特异性约束）。

更糟的是过拟合。RL 策略对训练集中见过的危机模式有效，对全新模式无效。而且——**RL 策略可能在"看起来像但不完全是"的历史危机模式上做出错误反应**。真实免疫系统给花粉过敏是经典案例——无害的花粉蛋白恰好和某种寄生虫蛋白共享一个表位。你的 B 细胞会过敏。

---

## 裂缝四：约束的组合动力学未知——α 的两难

7 条铁律。α 项。η 阈值。N_max。TTL。胸腺筛选。观察期。

每一个约束单独看都是合理的。但它们的组合动力学没有被证明。

α 项把 trust 拉向局部均值——但如果 α 太大，整个体液池变成一个"平均场"，所有 Agent 的 trust 趋同。丧失了异质性。B 细胞的 RL 策略依赖差异性——如果所有 Agent 都一样，策略学到的是平均行为，失去了特异性。

**α 太大 → 群体思维 → 免疫系统无法区分"大家都对"和"大家都错"。α 太小 → 无缓冲 → 单个 Agent 的塌缩自由传播。**

α 的最优值在哪？不同体液池的 α 应该不同——组织液池的 α 应该大于淋巴池的 α（局部更紧密耦合）。但怎么确定？靠试错？试错的过程就是让系统在真实危机中崩溃的过程。

**约束式工程的"可设计性"在约束数量超过某个阈值后非线性下降。** 这个阈值可能是 7±2（认知心理学的工作记忆上限）。超过这个数量，人的设计能力无法推理约束之间的组合效应。

---

## 裂缝五：我们仍在设计约束——终极承诺尚未兑现

约束式工程的终极承诺是：**约束从数据和环境中自行浮现，人只定义最底层的物理定律。**

但看看我们加了多少"人定义的约束"：`|d(trust)/dt| > η` 中的 η、N_max、TTL、胸腺筛选的历史数据集边界、α——每一个都是人设的。

**这不算背叛——但算坦率。** 我们还没有达到"约束自行浮现"的阶段。我们是在用约束式工程的思维来**指导设计决策**，但最终写进代码的约束仍然来自人的判断。

当前的阶段精准定位：**人工约束，人工涌现约束。** 不是成熟约束式工程的"域约束自动收敛"。但也不是启发式工程的"数据倒推规则"。人在定义约束，但约束的合法性来源是公理推导而非经验试错。

---

## 裂缝六：证伪性——如果理论永远不错，它就不是科学

波普尔：一个理论如果是科学的，必须存在一个可能的观察结果可以证明它是错的。

"约束式工程比指令式工程更好"——这句话能被证伪吗？

如果你造了一个约束式系统，它表现很好——证明有效。如果它崩溃了——你可以说"是约束没设对"、"是数据不够"、"是参数没调好"。**约束范式本身永远不会错。错的永远是具体的约束参数。**

这是所有大理论的通病——马克思主义、弗洛伊德心理学、复杂适应系统理论——它们都有完美的"免疫策略"来化解反例。反例永远被解释为"条件不满足"而不是"理论本身错了"。

**约束式工程论有这个风险。** 要避免它，必须主动声明约束范式的**适用边界**——在什么条件下它比指令式工程更差。

---

## 域约束：进化的引擎，而非终点

> **域约束**：一个在 N 个独立域中都不需要调整就能工作的约束。N 越大，它越不可能是你设计的产物，越可能是你发现的物理定律。

约束的进化层次：

| 层级 | 约束来源 | 当前状态 |
|------|---------|---------|
| L0 — 单域约束 | 你从公理推导，在单域验证 | ✅ 铁律在 Agent 域已实现 |
| L1 — 域特化约束 | 同一个约束在不同域取不同参数值 | 待多域并行 |
| L2 — 跨域不变约束 | **域替你筛出来的**——N≥3 时收敛 | 目标：游戏引擎 + Agent + 具身智能 |
| L3 — 约束生成器 | 跨域失效模式 → 自动生成新约束的结构 | 渐近线，非近期目标 |

**约束式工程的进化速度 = 域数量 × 域内的选择压力频率。** 单域、低频反馈 → 约束进化速度 ≈ 0。多域、高频反馈（三个域的模拟器同时跑，每帧都是选择压力）→ 约束进化速度足够大。

这就是为什么要同时推进游戏物理引擎、Agent 框架和具身智能——不是精力分散，是用**空间换时间**，人工制造并行的选择压力。每多一个域，活下来的约束就少一分"凑巧能用"的概率，多一分"物理定律"的证据。

---

## 早期约束式工程 ≠ 启发式工程

表面行为相同——都是人在定义规则。但合法性来源不同。

| | 启发式工程 | 早期约束式工程 |
|---|---|---|
| 约束形式的来源 | 数据 → 模式 → 规则 | 公理 → 推导 → 约束 |
| 数据的角色 | **权威**——决定规则是什么 | **校准器**——只决定参数值 |
| 当数据说"这条规则不对"时 | 修改规则 | 检查推导是否有未覆盖的边界条件 |
| 方法论承诺 | 无——数据是终极权威 | **有——"数据不得成为形式的唯一权威"** |

区分标准不是"谁定义的规则"——是**规则从哪里获得合法性**。

Lipschitz 0.30 不是"试了 0.22、0.30、0.50，0.30 效果最好"。是从"如果状态在两帧之间能无限跳变，ODE 积分器的收敛性无法保证"这个公理推导出来的。0.30 的值需要在不同域标定——但 Lipschitz 约束的**存在性**不依赖经验。它依赖数学。

同一条规则，如果它的合法性来源是公理推导 → 约束式工程。如果它的合法性来源是经验试错 → 启发式工程。**同样的代码。不同的范式归属。**

## 适用的边界条件

综合以上裂缝，约束式工程比指令式工程更好的条件：

1. **样本量门槛**：系统必须有足够的交互数据来校准约束参数。单用户 Agent 的数据积累速度可能不够——约束式工程在**个人助手**场景下可能天然劣于指令式工程
2. **信号冗余度门槛**：单信号源的免疫触发 = 单点故障。需要至少一个独立于主信号的验证维度
3. **约束数量门槛**：约束超过 7±2 个时，组合动力学超出人的推理能力，可设计性非线性下降
4. **多域验证门槛**：域数量 ≥ 3 时，跨域不变的约束才开始收敛。单域验证的约束可能只是"凑巧能用"
5. **不可预测性的容忍度**：拓扑白盒承认"无法预测精确轨迹"。在航空/核电等需要 100% 确定性的场景下不可接受

**当以上条件不满足时，指令式工程仍然是更好的选择。**

---

## 一条诚实的结论

> 约束式工程不是"更好的工程范式"。它是在样本充足、信号冗余、约束数量可控、多域验证可行、且设计者能容忍不可预测性的条件下，比指令式工程更鲁棒的工程范式。
>
> 我们当前处于约束式工程的早期阶段——人工推导约束，人工涌现约束。这不是启发式工程的子集，也不是成熟约束式工程。它是约束范式发展曲线上一个必要的、可区分的阶段。
>
> 最终关卡"约束从约束里面涌现"尚未攻克。通向它的路径是域约束的跨域收敛——当域数量足够多、选择压力足够大时，活下来的约束不再是你设计的，而是你发现的。但这一天还没有到来。在此之前，保持坦率。
