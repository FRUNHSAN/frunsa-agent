# 10 — 约束式工程实践方法论

**Last-verified-against-code**: `7e73374` (2026-07-04)
**预计阅读时间**: 12 分钟
**文笔配比**: 灵感 10 : 严谨 90 — 可机械执行的检查清单

---

从"为什么"到"怎么做"。在设计任何新功能、新约束、或修改已有约束之前，按以下 6 步强制检查清单执行。

---

## 步骤 1：这个功能是约束还是指令？

**判断标准**：如果删除它，系统还能自己找到解吗？

- **是** → 约束。保留。系统在约束定义的可行域内自行收敛。
- **否** → 指令。尝试改写为约束，或显式标注 `[类型: 指令]`——在约束式工程中，指令是最后手段，不应成为主要建筑材料。

**快速测试**：用否定句表述——"系统不能做什么"。如果不能精确描述 → 大概率是指令。

**例子**：
- "Agent 应该先反思再执行" → 指令，不是约束。删除后系统无法自行发现"反思"步骤
- "Agent 的 trust 变化速率不能超过 0.30/帧" → 约束。删除后 trust 仍会变化——只是可能突变

---

## 步骤 2：约束的公理来源是什么？

**约束形式的合法性必须能追溯到某条铁律或某个已证明的数学不变量。**

追溯链格式：
```
约束 C → 推论 Y → 定理 X → 铁律 #N
```

如果追溯不到 → 这不是约束。这是经验。按 Protocol 1 标注 `[来源: 经验推测] [置信度: LOW]`。

**约束的置信度只来自公理推导链的长度和严密性，不来自实验数据。** 实验数据只能标定参数。

---

## 步骤 3：参数和形式的分离

**形式来自推导，参数来自标定。两者不得混淆。**

对每一条约束，填写：
```
约束名称: [NAME]
[形式]: [数学表达式] ← 来自: [公理推导链]
[参数]: [变量名 = 当前值] ← 来自: [标定数据/默认值]
[形式不可修改条件]: [为什么这个形式是公理推导的唯一可能形式]
[参数可修改条件]: [什么数据可以更新这个参数值]
```

**红色警报**：如果用一个 AB 测试结果来论证"形式应该改成 X"→ 12-反模式 #9（数据权威篡位）。

---

## 步骤 4：跨域压力测试计划

**这个约束在三个域中分别会被怎样考验？**

| 域 | 预期行为 | "死亡"条件 | 测试方法 |
|----|---------|----------|---------|
| 游戏引擎 | [在 ms 级模拟中如何表现] | [穿透/SDF违反/实时超限] | [楼梯demo / 压力测试] |
| Agent 对话 | [在秒级对话中如何表现] | [信任跌破floor/免疫风暴] | [PLAN2盲测 / 模拟器] |
| 具身智能 | [在实时控制中如何表现] | [碰撞/力矩超限/紧急停止] | [ROS2仿真 / 真实机器人] |

如果约束对某个域不适用 → 明确标注 `[域: NOT_APPLICABLE]`。不是回避——是承认这个约束只覆盖部分域。域通用度 G(C) < 1.0。

---

## 步骤 5：退化模式枚举

**如果这个约束失效，系统会以什么方式崩溃？有没有安全的退化路径？**

枚举格式：
```
[正常模式]: 约束生效时的系统行为
[退化模式 1]: 约束参数轻微失效 → 系统行为 → 可恢复？
[退化模式 2]: 约束形式部分失效 → 系统行为 → 可恢复？
[退化模式 3]: 约束完全失效 → 系统行为 → 可恢复？
[安全的退化路径]: 从退化恢复的步骤
```

**如果退化模式 3 不可恢复（即约束完全失效 = 系统崩溃）→ 这是硬约束。硬约束需要额外的冗余保护（Safety Arbiter 三层降级、白细胞分化的 N_max）。**

---

## 步骤 6：约束的生命周期管理

**每个约束必须声明生命周期状态。**

生命周期状态机：

```
PROPOSED  →  ACTIVE  →  STALE  →  DEPRECATED  →  ARCHIVED
                ↑                       │
                └───────────────────────┘
                       (REVIVED)
```

| 状态 | 含义 | 触发条件 |
|------|------|---------|
| `PROPOSED` | 新提出，未经验证 | 初始状态 |
| `ACTIVE` | 正在使用，定期审查 | 通过步骤 1-5 验证 |
| `STALE` | 连续 3 次迭代未触发 | Protocol 7 审查 |
| `DEPRECATED` | 标记废弃，等待归档 | 人类确认废弃 |
| `ARCHIVED` | 移入 archive/，保留元数据 | 经过观察期（≥1个里程碑） |
| `REVIVED` | 从 STALE 恢复为 ACTIVE | 新场景重新需要此约束 |

**废弃不等于删除。** 已废弃的约束移入 `archive/deprecated/`，保留：废弃日期、取代者 ID（如有）、废弃原因。禁止物理删除——对应生物学的假基因（pseudogene）。

## 约束设计模板

标准化的约束定义格式——写入 `CLAUDE.md` 或 `.ai_reasoning/chains/` 时使用：

```
[CONSTRAINT: C_XXX]

名称: [一句话描述]
公理来源: [推导链: 约束 C → 推论 Y → 定理 X → 铁律 #N]
数学形式: [表达式]
参数表:
  - [参数名] = [当前值] (来自: [标定数据/默认值])
  - ...
域通用度: G(C) = [1.0 / 0.5 / 0.33 / ...]
  已验证域: [游戏引擎 / Agent对话 / 具身智能]
  未验证域: [...]
退化模式:
  - [退化1]: [描述] → [可恢复/不可恢复]
  - [退化2]: ...
生命周期: PROPOSED | ACTIVE | STALE | DEPRECATED
最后审查: YYYY-MM-DD (Protocol 7)
取代者: C_XXX (如适用)
```

## 启发式入侵检测

以下三句话出现时，**你已经滑向启发式工程**。立即停止。回溯公理推导链。

| 红色警报 | 为什么危险 | 应该说什么 |
|---------|----------|----------|
| "我们试了这个值，效果最好" | 参数来自试错，不是来自标定 | "这个参数的标定数据来自 [X]。置信区间为 [Y]" |
| "参考了 XX 框架的做法" | 合法性来自外部权威，不是公理 | "XX 框架的做法恰好符合铁律 #N 的推论，因为 [推导]" |
| "A/B 测试显示显著提升" | 数据在决定形式，而不是标定参数 | "AB 测试确认了参数 Y 在域 Z 中的最优值。约束形式来自铁律 #N，不受此次测试影响" |
