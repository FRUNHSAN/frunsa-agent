# 从连续数学到离散工程

**V7.8 自检报告** | 2026-06-11

---

## 审计结论

V7.2→V7.7 构建了层论、纤维丛、梯度流、路径积分等数学模型。
代码审计发现三个系统性裂缝：

### 陷阱 1：伪连续

**数学**: `c' = c - η∇V` 连续梯度。**代码**: `_build_contract_directive()` 是 4 段 if/else 中文模板。Planning LLM 完全不收契约指令——`_do_plan()` 接收 `system` 参数但函数体内零引用。

→ **修补**: `VERBOSE_CONTINUUM` + `TONE_CONTINUUM` 替代硬编码 `v_map`/`tone_map`。过渡期用中点词数平滑切换，契约微小变化真正影响生成指令措辞。

### 陷阱 2：伪梯度

**数学**: `∇V` 势能场梯度下降。**代码**: `_contract_adapt()` 是 `if clarity_count > 3: proposal = "THEORETICAL"`。`V` 函数不存在。`CROSS_COEFFICIENTS` 是手写的 7 个猜测值。`MAX_GRADIENT_NORM = 0.3` 定义了但从未校验。

→ **修补**: `_check_lipschitz()` 在每次 sensor-driven proposal 前校验 `|new_ordinal - current_ordinal| / max_ordinal ≤ 0.3`。超限拒绝。

### 陷阱 3：单向膜

**数学**: `⊥` 开集——截面未定义，层论上同调非平凡区域。**代码**: `_classify_null_region()` 的 50 行输出最终只流入 `return None`。Agent 感知到语义真空后……什么都没做。

→ **修补**: `_clarification_needed` flag。null_region 或 gap_region 触发时，注入 `[语义状态] 上一轮输入处于语义模糊区域。请礼貌澄清，不要猜测。` 到 system prompt。仪表盘→执行器。

## 明确承认的工程妥协

以下不做——是诚实的 MVP 边界，不是 bug：

| 妥协 | 原因 | 未来 |
|------|------|------|
| ∇V 从数据学习 | 需要用户隐式反馈的奖励模型。手写 streak 是合理的 MVP | V9.x |
| 连续向量→LoRA 权重 | 需要微调基础设施 | V10+ |
| CROSS_COEFFICIENTS 从数据学 | 需要联合分布标注。7 个手写系数在 6 类命令上够用 | V7.9 |
| Planning LLM 收契约指令 | `_do_plan()` 接口改动影响 Track C 全链路 | V7.9 |

数学是设计图纸，代码是施工脚手架。剩下的 38% 差距不是偷懒——是承认有些桥需要更大的船才能过。
